# 0.6元の提示価格が実際は6元に：API中継業者の10倍過剰請求の闇と不正検知の手引き

APIの利用料金やクラウドアカウントの監査を専門に行う立場から見ると、価格情報の非対称性を悪用してエンジニアをカモにする手法は後を絶ちません。少しでも開発コストを圧縮しようと、ネット上で格安を謳うサードパーティの中継サービスに飛びつき、騙されてしまうケースが頻発しています。

しかし、安易な甘い話の裏には必ず巧妙な仕組みが存在します。

先日、技術フォーラムV2EXにおいて、極めて悪質な過剰請求の実態が暴露されました。あるエンジニアが格安を掲げる中継業者を利用したところ、トップページには100万入力トークンあたりわずか0.64元という破格の単価が表示されていました。

通常の計算であれば、数万トークンのテキスト処理を行ったところで、発生する料金は数分程度に収まるはずでした。

ところが、処理終了後に管理画面の残高引き落とし履歴を確認した利用者は絶句しました。実際に差し引かれていた金額は、提示されていた公称価格の実に10倍に達していたのです。サポートに事実関係を問い合わせたところ、返ってきたのは呆れた言い訳でした。「当プラットフォームは段階制ルーティングを採用しており、全体最適化により自動的に高単価な回線へ割り振られたため仕様通りの請求である」という主張でした。

今回はこの悪質な手口の裏側を徹底的に暴き、提示価格の裏に潜むカラクリを見抜くための点検手順をお伝えします。

---

## 一、 被害の実態：格安の看板を掲げ、裏で密かに10倍を徴収する

まずは実際に告発された取引明細の数値を検証します。

被害に遭ったエンジニアが利用した際、プラットフォームのトップページに掲示されていた見せかけの価格設定は以下の通りでした。

| 項目および入力仕様 | サイト上の提示価格 | 実際に適用された引き落とし単価 | 請求倍率 |
| :--- | :--- | :--- | :--- |
| 入力プロンプトトークン | 100万トークンあたり0.64元 | 100万トークンあたり6.40元 | 正確に10.0倍 |
| 出力補完トークン | 100万トークンあたり3.20元 | 100万トークンあたり32.0元 | 正確に10.0倍 |
| キャッシュ読み込み | 100万トークンあたり0.03元 | 裏側で同様に拡大適用 | 倍率上乗せの疑い |

この単一リクエストにおける実際の数学的計算は以下の通りです。

* **実際のリクエスト入力数**：42,991トークン。
* **公称価格に基づく理論上の利用料**：42,991を1,000,000で割り0.64元を掛けると、本来請求されるべき金額は0.0275元。
* **口座残高から実際に引き落とされた額**：0.2751元。

実際の差し引き金額と本来の請求額の比率は、誤差なく正確に10.00倍に達していました。

明細ログを証拠として突きつけられても、業者は不具合を認めるどころか、自社のルーティングアルゴリズムが高品質回線を選択した結果であると開き直りました。

提示する看板価格と実際の請求体系が完全に乖離している以上、これは従量課金ではなく意図的な搾取に他なりません。

## 二、 手口の解剖：悪質業者が用いる3大詐術

なぜこれほど露骨な過剰請求が横行するのでしょうか。

理由は明白です。ほとんどの開発者はAPI呼び出しの1回ごとに残高明細を電卓で突き合わせるような確認を行わないからです。自動化されたスクリプトから大量に呼び出される中で、残高が減っていくのを見ても「それだけ多く使ったのだろう」と思い込み、裏で10倍の係数が適用されているとは夢にも思わないのです。

監査の現場で確認される悪質な手口は主に以下の3つに集約されます。

### 1. 手口1：見せかけの低価格と隠蔽されたグループ倍率設定

オープンソースの中継基盤ソフトウェアの多くは、ユーザーグループごとに課金倍率を設定できる機能を備えています。悪質業者は一般向けの表示単価を極限まで低く設定しておきながら、実際のAPIトークンが発行された裏側では、ユーザーを5倍や10倍の係数が設定された特別グループへ自動的に割り振ります。

トップページの価格は単なる集客用の撒き餌に過ぎず、残高をチャージして利用を始めた瞬間から水増しされた倍率で残高が削られていきます。

### 2. 手口2：スマートルーティングを口実にした高額回線への誘導

多くの業者が「自動フェイルオーバー」や「AIによる最適回線選択」をアピールします。

信頼できるサービスであれば、負荷分散は可用性の確保とコスト削減のために機能します。しかし悪質なプラットフォームでは、この仕組みがクレームに対する格好の言い逃れとして悪用されます。「安価な回線が混雑していたため、親切心で高単価なバックアップ回線に切り替えた」と主張し、責任をアルゴリズムに転嫁するのです。

### 3. 手口3：高額請求の裏で行われる低品質モデルへのすり替え

さらに悪質なケースでは、法外な10倍の料金を徴収しながら、実際に呼び出しているモデルを廉価な小型モデルやすり替え版に格下げしている事例すら存在します。

高精度なフラッグシップモデルを指定してリクエストを送っているにもかかわらず、裏側では無料のスクレイピングエンドポイントや8Bクラスの軽量モデルを応答させて暴利を貪ります。その結果、高額な利用料を支払わされながら、出力される回答は支離滅裂なものになります。

## 三、 課金監査員直伝：1分で完了する3段階の自己監査プロトコル

サードパーティの中継サービスを利用しているすべての開発者に、以下の手順で即座に残高明細の自己点検を行うことを強く推奨します。

### 1. ステップ1：単一リクエストの詳細ログを抽出する

管理画面の呼び出し履歴から、直近の完了した独立リクエストを1件選び、記録された数値を書き出します。

* 入力トークン数 prompt_tokens
* 出力トークン数 completion_tokens

### 2. ステップ2：公称価格に基づく理論費用を手計算する

トップページに記載されている約束単価を用いて、本来支払うべき理論金額を算出します。

```text
理論上の利用料金 = 入力数 * 入力単価 / 1000000 + 出力数 * 出力単価 / 1000000
```

### 3. ステップ3：適用されている実質倍率を判定する

管理画面で実際に差し引かれた金額を、先ほど算出した理論費用で割ります。

```text
実質倍率 = 実際に差し引かれた金額 / 理論上の利用料金
```

* 倍率が1.0であれば、適正に課金されています。
* 倍率が1.1から1.5の間にある場合、明示されていない為替マージンや手数料が上乗せされています。
* 倍率が2.0や10.0に達している場合、故意に設定された過剰請求トラップに嵌まっています。即座に利用を停止してください。

## 四、 コスト管理における健全な基本原則

理不尽な不利益を被ることなく開発を進めるために、以下の3大原則を遵守してください。

* **初回は少額チャージに留め、即座に照合を行う**：実績のない新規サービスを利用する場合、事前の宣伝文句に惑わされず、最初の入金はごく少額に抑えます。接続テストが完了したら直ちに上記の自己監査を行い、計算通りの引き落としが行われているか確認します。
* **大手クラウド公式の従量課金を最優先にする**：アリババクラウドや火山エンジンなど、大手事業者の公式コンソールは少額からの透明な従量課金に対応しており、不透明な倍率操作の余地がありません。複数モデルを跨ぐ場合も、運営体制が明白で監査性の高い事業者を選定します。
* **データガバナンスと機密保持の意識を持つ**：素性の定かでない無認可の中継業者に社内コードや機密プロンプトを送信することは、不当な請求を受けるリスクだけでなく、データそのものが中間で抜き取られて転売される致命的なセキュリティリスクを伴います。

計算リソースは開発者にとって貴重な資産です。見かけの安さに惑わされることなく、自身の権利と資産を堅実に防衛してください。
