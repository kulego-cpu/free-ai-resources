# 12GB VRAMで4-bit MoEを24 t/s駆動：BetelgeuseエンジンとデュアルチャネルDMA実測

ローカルAI環境の構築において、VRAM不足は常に最大の壁です。手元にRTX 3060 12GBと16GBのホストメモリという定番構成を抱えるユーザーは世界中に数多く存在します。しかしQwen 3.8 Flash Nextをはじめとする最新の混合エキスパートモデルを動かそうとすると、12GBのVRAMでは全エキスパートを収容できず、従来のllama.cppによるCPUオフロードでは激しいメモリスワップが発生し、秒間わずか0.5から0.6トークンという実用不可能な水準まで速度が落ち込みます。

巨大なMoEモデルの運用には高価な複数枚GPUが不可欠と考えられていた中、オープンソースの推論エンジンBetelgeuseが劇的な実測結果をもたらしました。

標準的なRTX 3060 12GBと16GBメモリの環境において、Betelgeuseは4-bit量子化MoEモデルの生成速度を毎秒24トークンまで押し上げることに成功し、しかも**エキスパートを一切スキップしない完全なByte-Exact精度**を維持しました。

さらに実測で明らかになった最大のボトルネックは、**メモリ構成をシングルチャネルからデュアルチャネルに変更しただけで、速度が14 t/sから24 t/sへと跳ね上がった事実**です。これは単なるオカルト的チューニングではなく、バス帯域幅の物理的制約を打破した明確な成果です。

## 1. ベンチマーク環境と各推論エンジンの性能比較

公平な性能評価を行うため、同一の格安PC環境を用いて厳密な比較検証を実施しました：

### テスト環境のスペック詳細

| 構成要素 | 仕様パラメータ |
| :--- | :--- |
| **GPU** | NVIDIA GeForce RTX 3060 12GB VRAM版 |
| **システムメモリ** | 16GB DDR4、1枚挿しシングルと2枚挿しデュアルを比較 |
| **OS環境** | Ubuntu 24.04 LTS、最新NVIDIA 550系ドライバ適用 |
| **対象モデル** | Qwen 3.8 Flash Next、4-bitおよび8-bit量子化各種 |
| **比較エンジン** | llama.cpp最新版、Strata低メモリモード、Betelgeuse |

### 実測スループットの比較結果

同一マシン上で各種量子化とメモリチャネルを変更した際の実測速度は以下の通りです：

| 量子化形式と精度 | メモリ物理構成 | llama.cpp | Strata低メモリ設定 | Betelgeuse 実測値 |
| :--- | :--- | :--- | :--- | :--- |
| **IQ4_XS 4-bit精度** | 16GB 1枚挿しシングル | 約 0.5 t/s、激しいスワップ | 4〜5 t/s | **14.0 t/s** |
| **IQ4_XS 4-bit精度** | 8GB 2枚挿しデュアル | 約 0.6 t/s、激しいスワップ | 5〜6 t/s | **24.0 t/s 快適実用水準** |
| **IQ2_XS 極限量化** | 16GB 1枚挿しシングル | 1.47 t/s | 8.11 t/s | **22.03 t/s、瞬間最大48 t/s** |
| **Q8_K_XL 8-bit高精度** | 16GB 1枚挿しシングル | メモリ溢れで起動不可 | コールド8 t/s、ウォーム12 t/s | **約 10.0 t/s 安定動作** |

Betelgeuseで得られたすべての結果は、出力内容の検証において100パーセントの一致が確認されており、精度低下やエキスパート脱落は一切ありません。

## 2. なぜメモリ増設だけで速度が倍増するのか

実測データの中で最も衝撃的なのは、同じ16GBという容量でありながら、シングルチャネルからデュアルチャネルへ切り替えるだけで速度が14 t/sから24 t/sへ約1.7倍も急増した点です。

この挙動は、コンピュータのメモリバス帯域幅から明快に説明できます：

### シングルチャネルによるPCIe帯域のボトルネック
MoEモデルでは、トークンを1つ生成するごとに異なるエキスパート層を動的に呼び出す必要があります。エキスパート群がホストメモリ上にある場合、前向計算のたびにPCIeバス経由でGPUへ重みを転送しなければなりません。
- DDR4メモリ1枚によるシングルチャネル駆動時の実効転送帯域は約19 GB/sにとどまります。
- この速度ではPCIe 3.0や4.0の帯域幅を満たすことができず、GPUの演算コアはデータ到着を待つアイドル状態に陥ります。

### デュアルチャネル化による転送パイプラインの開放
- 8GBメモリ2枚によるデュアルチャネル構成にすると、ホストメモリの理論読み出し帯域幅は一挙に約38 GB/sへ倍増します。
- メモリコントローラが倍の速度でテンソルをPCIeバスへ供給できるようになり、GPUの待機時間が大幅に削減されます。これがメモリ容量を一切増やさずとも大幅な速度向上を果たせる物理的理由です。

## 3. Betelgeuseエンジンの独自アーキテクチャ

なぜ既存のllama.cppが失速する一方で、Betelgeuseはこれほどの高速化を実現できるのでしょうか。その理由はMoE専用に研ぎ澄まされた2つの設計にあります：

### 専有型ホストメモリ犠牲キャッシュ
一般的なメモリ管理では、退避された重みがOSの一般的なファイルキャッシュと混在し、無駄な再確保オーバーヘッドが発生します。BetelgeuseはホストRAM上に専用の犠牲キャッシュ領域をあらかじめ確保し、頻繁に利用されるエキスパートをナノ秒単位のレイテンシで管理します。

### ハードウェア非同期DMAパイプライン
従来のソフトウェア転送ではCPUが頻繁に介入し割り込み負荷を生じさせます。BetelgeuseはGPU側のメモリコントローラからホストRAMへ直接アクセスするハードウェアDMAチャネルを活用。現在のトークン計算を行っている裏で、次のステップで必要となるエキスパート重みをDMA経由で非同期に事前転送し、計算と転送の完全なオーバーラップを実現しています。

## 4. 盲信を防ぐための実用上の境界条件

過度な期待やトラブルを防ぐため、Betelgeuseの現時点での制限事項や注意点も正確にお伝えします：

### ハイスペック環境での逆転現象に注意
コミュニティの報告によると、RTX 4080 Superと64GBメモリという上位マシンで同一のQ8モデルを実行した際、速度が3.28 t/sまで急激に落ち込む現象が観測されています。
現在のBetelgeuseはAmpere世代のRTX 30系に特化した最適化が含まれており、Ada Lovelace世代のアーキテクチャや大規模メモリ環境ではバス競合が発生する可能性があります。

### ハードウェア互換性の現状
開発が進行中のプロジェクトであるため、AMD RadeonのROCm環境や8GB未満のVRAMしか持たないカードへの対応は発展途上です。業務環境への本番導入には事前の検証が必要です。

## 5. 実機セットアップと起動手順

手元にRTX 3060 12GBマシンをお持ちで、この性能を試してみたい方向けの標準セットアップ手順です：

### デュアルチャネル構成の確認
まずターミナルで以下のコマンドを実行し、メモリが正しくデュアルチャネル駆動しているか確認します：

```bash
# メモリスロットと動作クロックの確認
sudo dmidecode --type memory | grep -E "Locator|Speed|Configured Memory Speed"
```

マザーボードのマニュアルで指定された推奨スロットにメモリが装着されていることを確認してください。

### Betelgeuseサーバーのビルドと起動

```bash
# リポジトリのクローンとコンパイル
git clone https://github.com/zyxciss/betelgeuse.git
cd betelgeuse
make -j$(nproc)

# 必須環境変数：非同期ハードウェアDMAを有効化
export MOE_DMA=1
export HOST_VICTIM_CACHE_MB=12288

./bel-server \
  --model ./qwen3.8-fn-iq4_xs.gguf \
  --n-gpu-layers 33 \
  --ctx-size 8192 \
  --port 8080
```

起動後はOpenAI互換の各種UIクライアントから接続し、リアルタイムのトークン生成速度を体感できます。

## 6. まとめとコスト効率の高いアップグレード方針

今回の実測検証は、限られた予算で最先端AIを動かしたいユーザーにとって極めて有益な示唆を与えてくれます：
MoEモデルの時代において、**推論体験を左右する最大のボトルネックはGPUの演算性能そのものよりも、システム全体のメモリ転送帯域幅に移行しています**。

高額な費用を払ってわずかに性能の高いGPUへ買い替える前に、まずは数千円で同規格のメモリをもう1枚増設しデュアルチャネル化を図ること。この小さな見直しが、手元の旧型グラフィックボードを驚異的な主力機へと蘇らせてくれます。
