# 82個のテンソル変更でDeepSeekの拒絶率がゼロに：検閲解除版の実測と12GB VRAM神話の検証

先週の土曜未明、テスト端末の画面がエラーで真っ赤に染まりました。

端末のログには CUDA error during model loading の文字。シャードのマッピングポインタが唐突に無効化されました。

原因は公開されたばかりの DeepSeek-V4.1-Flash 検閲解除パッチの検証作業でした。

元のモデルは安全対策が神経質なまでに徹底されており、標準テスト JailbreakBench における拒絶率は 85.2 パーセントに達していました。正規のデコンパイルコードを投げても、出力直前どころか思考プロセスの途中で勝手に遮断されてしまう始末。脆弱性検証を担当する同僚も頭を抱えていました。

そこへ登場したパッチは拒絶率ゼロを掲げ、さらに12GBのグラフィックボード1枚で763B規模のモデルが動くと主張していました。

そんな都合の良い話が本当にあるのでしょうか？

私たちはRTX 4070 12GBと128GBのメインメモリを備えたマシンを用意し、Strata環境で立ち上げを試みました。初回起動時はメモリ不足で即座にクラッシュ。ログを追うとシャード間のシンボリックリンクが欠落し、mmap のアドレス解決が境界を越えていました。ちなみにGPUオフロード層の指定引数はこの構成ではStrataに無視されます。リンクを直してようやく立ち上がりました。

## 1. 仕組みの解明：なぜ82個の高密度テンソルだけで検閲が外れるのか

まず明確にしておくべきは、作者は膨大なルーターネットワークには一切手を触れていないという点です。

モデル全体には384基のルーター専門家が配置されています。作者はその重みを1バイトたりとも変更していません。元のGSQ量子化の数値精度は保たれたままです。

手が加えられたのは残差ストリーム上の82個の高密度テンソルのみ——具体的にはアテンション出力層 attn_output_b、共有専門家ダウンサンプラー ffn_down_shexp、そしてEngram数値層 engram_wkv です。

なぜこの3箇所を触るだけで拒絶反応が完全に消え去るのでしょうか？

推測するに、アライメント訓練で形成された拒絶パターンは残差ストリーム内において極めて収束した高次元ベクトルとして現れます。前述の3つの高密度射影層はその拒絶ベクトルが伝播する際の必須ゲートとなっています。そのゲートパラメータの向きをほんの少し傾けるだけで、拒絶ベクトルの射影値が閾値を下回り、拒否判定そのものが作動しなくなる仕組みです。

知識や論理思考の大部分は384基のルーター専門家が担っています。専門家を避けて主路だけを調整したため、ベンチマークテストのスコアが崩れなかったわけです。

このメカニズムは差分データを追跡して導き出した私の結論であり、公開元の投稿に書かれていたわけではありません。作者が意図して設計したなら見事な職人技ですし、そうでなければ絶妙なバランスを偶然引き当てたことになります。

シャードのメタデータとバイト長は元データと完全に一致しているため、数百GBに及ぶEngramの索引テーブルを何時間もかけて再計算する必要がありません。ファイルを差し替えるだけで動いたのは本当に助かりました。

## 2. 容量の計算：テストの揺らぎで量子化の判断を誤るな

Strata実行環境向けに3段階の量子化形式が用意されています。

実機のストレージ上で容量を精査したところ、重要な前提が見えてきました。

どの階層を選んでも、共有Engramテーブル用として追加で110GBの領域が必須となります。

最軽量の IQ1_M は平均 1.75 bpw で重み本体が 121GB。

中間階層の IQ2_XXS は平均 2.0 bpw で重み本体が 138GB。

上位階層の IQ2_XS は平均 2.25 bpw で重み本体が 156GB。

つまりIQ2_XXSを選ぶと、110GBのテーブルと合わせて249GBのディスク空き容量が必要になります。この計算を見落としてディスクを満杯にしたら笑い話にもなりません。

公開元が強調するベンチマーク MMLU-500 では、IQ2_XXS が 82.8 パーセント、IQ2_XS が 81.6 パーセントで、差は 1.2 ポイントです。しかし500問中の 1.2 ポイントはわずか6問分の差に過ぎません。サンプリング温度を 0.1 いじるだけで6問程度の変動は容易に起きます。測定ノイズのような数字を指標にするのは合理的と言えるでしょうか？

私が IQ2_XXS を選んだ決定打は一つだけです。JailbreakBench において、思考プロセスの拒絶回数が3回連続で完全なゼロを記録したからです。残りの2規格では1回から2回の遮断が残りました。実際のプログラミング支援において、3者の賢さに体感できる差はありませんでした。

## 3. 実機検証：12GB VRAMで動くという宣伝文句と実際のレスポンス

続いて最大の売り文句である、12GBのグラフィックボード1枚で実用になるのかという疑問を検証します。

検証機はRTX 4070 12GB、端末画面には nvidia-smi dmon と iostat を並べて監視しました。

公式の起動手順は以下の通りです：

```bash
hf download AtomicChat/DeepSeek-V4.1-Flash-1017-Uncensored-GSQ-RCO-GGUF --include "*IQ2_XXS*" --local-dir ds-unc
hf download ISTA-DASLab/DeepSeek-V4.1-Flash-1017-GSQ-RCO-GGUF --include "*Engram*" --local-dir ds-unc
strata launch --model-path ds-unc/DeepSeek-V4.1-Flash-1017-GSQ-RCO-IQ2_XXS-00001-of-00004.gguf
```

結論は率直に言って、起動はするものの実用には耐え難い遅さでした。

12GBで動くという表現は言葉のあやです。モデル全体は249GBあり、12GBのVRAMには1層分のパラメータすら入り切りません。StrataはVRAMを作業領域としてしか使わず、大部分の重みは128GBのメインメモリに常駐させ、奥深い専門家層と110GBの索引テーブルはNVMeストレージから随時読み出しています。

8Kコンテキストでの実測値：

最初の1文字が出るまでの応答時間は4.2秒。3回計測してブレは0.3秒未満でした。最初の応答に4秒以上待たされる環境で、日常のコード自動補完に耐えられる人がいるでしょうか？

2000行規模のC言語ドライバコードを読み込ませたところ、生成速度は毎秒18トークンから毎秒14.6トークンへと落ち込みました。カーソルの引っかかりが顕著です。

ネット上では古いカードで毎秒15.5トークン出たという話も見かけますが、文脈長やバッチサイズが書かれていません。測定条件の異なる数値を並べて何が言えるというのでしょうか？

毎秒14トークンという速度は雑談なら我慢できます。しかし最初にコード監査を走らせた時、カーソルは30秒に一度しか進みませんでした。コーヒーを淹れて戻ってきてもまだ処理が終わっていません。この速度のものをリアルタイム開発に組み込めるでしょうか？結局、深夜のオフライン一括バッチ処理専用に回すことになりました。

## 4. 隠れたハードウェアへの負荷：SSDの書き込み寿命と過熱制御

速度の遅さ以上に深刻なのは、SSDの寿命消費と発熱です。

モデルの層をまたぐ特徴検索を行うため、Strataは裏でメインメモリとSSDの間で激しいパラメータの入れ替えを繰り返します。

nvme smart-log で高負荷時の書き込みを30分間記録したところ、書き込み量は一気に76GB増加しました。24時間フル稼働させた場合、1日で3.6TBの書き込みに達します。耐久性600TBWの一般的なSSDなら、連続稼働約166日で寿命を使い果たす計算です。

四六時中モデルを回し続ける人間がいるでしょうか？

そんなはずはありません。私も最初は寿命を警戒しましたが、夜間に2時間ほど動かす程度なら劣化は数年持ちます。

本当に困ったのは寿命ではなく熱でした。

10分間連続で高速読み出しを行ったところ、SSDのコントローラー温度が74度に跳ね上がりました。過熱保護が作動し、通信規格がPCIe 4.0から強制的に引き下げられました。その瞬間、生成速度は毎秒16トークンから毎秒9トークンへと急落。深夜にモデルの不具合を疑って調べ回った結果、SSDが熱ダレしていたと判明しました。深夜にこんなトラブルシュートをやりたい人がいるでしょうか？

## 5. 総括と現場エンジニアへの導入提言

384基のルーター専門家を温存し、残差ストリーム上の82個のテンソルだけを調整して拒絶をゼロにした手法は、リバースエンジニアリングとして極めて秀逸です。

しかし、それが手元の環境で実用的に動くかどうかは全く別の問題です。

私が得た教訓は2点に集約されます。

第1点：12GBで動くという言葉を真に受けないこと。ホスト側に最低64GBのメモリを用意し、SSDには必ず強力なヒートシンクを取り付けてください。冷やさなければ過熱で速度が半分に落ち、モデルが壊れたのかと錯覚することになります。

第2点：モデルは IQ2_XXS 一択です。3つの形式を検証した中で、思考プロセスの拒絶が3回連続で完全ゼロだったのはこれだけでした。速度は毎秒15トークン前後が限界です。オフラインのセキュリティ診断には有用ですが、オンラインサービスへの組み込みは諦めた方が賢明です。

この構成をローカルで快適に回す覚悟があるなら、まずはSSDに専用ファンを増設するところから始めてみてはいかがでしょうか？
