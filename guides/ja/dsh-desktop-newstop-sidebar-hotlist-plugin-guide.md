# Agent の推論待ちに熱血トレンドを流し見：DSH Desktop 用サイドバー拡張 DS-NewsTop の構造と導入実測

ローカルで長時間の自動開発タスクを実行する。
例えば Agent にモジュール全体のリファクタリングを任せる場面。
モデルの推論には二分から三分程度の待ち時間が生じます。
ブラウザを開いてニュースを眺めるか？
タブを巡回しているうちに集中が切れてしまいます。
元の画面に戻った頃には、確認すべきコードの差分を忘れてしまうこともしばしばです。
AI クライアントの内部に軽量なサイドバーがあればどうでしょうか。
ターミナルの出力を監視しつつ、コミュニティの技術トレンドを斜め読みする。
読み終わればワンクリックで折りたたむ。
メインエディタの領域を圧迫しません。
手軽です。

オープンソース拡張 DS-NewsTop はこの課題に対応します。
DSH Desktop 専用に設計されており、Cordis モジュール機構を通じてサイドバーに各プラットフォームのトレンドを統合します。

## 1. アーキテクチャ解説：同一生成元プロキシとポーリング排除の設計思想

開発ツールに情報集約プラグインを組み込む際、最大の懸念は何でしょうか。
バックグラウンドでの無制限な定期ポーリングです。
多くの集約系拡張はリアルタイム性を標榜し、数分おきに数十の外部 API へ一斉リクエストを放ちます。
ローカルでコード推論を回している最中にポーリングが重なれば、ネットワーク帯域と CPU 資源を浪費します。
最悪の場合、画面の描画コマ落ちを招きます。

DS-NewsTop の設計思想は非常に抑制的です。
構造は主に三つのレイヤーに分かれています。

### 1. ホスト側同一生成元エンドポイントとインメモリキャッシュ
サイドバーの Webview は外部プラットフォームへ直接クロスオリジン通信を行いません。
ホスト側のメインプロセス lib/index.js に統合エンドポイントを定義しています。
`/dsh-hot-list/items?id=sourceID`
フロントエンドはローカルの同一生成元インターフェースのみを参照します。
ホスト層に 60 秒のインメモリキャッシュを内蔵。
短時間にサイドバーを開閉してもメモリから即座に応答し、余分な外部パケットを発行しません。
高速です。

### 2. データ集約とパース処理
データ取得ルートは二系統に整理されています。
GitHub、Hacker News、V2EX、Qiita 類似の知乎など 18 サイトはオープンソースの NewsNow サービスを経由します。
小衆ソフトウェア発見チャンネルの Markdown ページは個別パーサーで処理し、固定ルール投稿を除外して上位の共有情報を抽出します。
ホストコードはリクエスト先を固定しており、フロントエンドから任意の外部 URL を受け取らないため、プロキシ悪用を防ぎます。
安全です。

### 3. オンデマンド更新への割り切り
このプラグインには自動定期ポーリング用タイマーが存在しません。
パネルを開いた時のみ有効化されたカードを読み込みます。
パネルを閉じている間は通信を行いません。
手動での単一カード更新または全カード更新により最新情報を取得します。
手動更新時は 60 秒キャッシュをバイパスして上流へ再送します。
仮に上流サービスが応答不能となった場合でも、直前の取得データを画面に保持したまま再試行ボタンを提示し、画面クラッシュを防ぎます。
堅牢です。

## 2. 互換性の境界条件とリソース負荷の実測

開発機環境において連続三時間の稼働テストを行い、各指標を記録しました。

### テスト環境のスペック
- ホスト環境：DSH Desktop 2.0.18、コア互換バージョン 0.2.1-rc.2 および 0.2.1-rc.3
- ハードウェア：M2 Max 搭載 MacBook Pro、32GB 統合メモリ
- プラグインバージョン：dsh-hot-list 1.3.2 安定版

### 実機動作におけるリソース比較

| 評価指標と状況 | 通常ブラウザで複数タブ閲覧 | DS-NewsTop サイドバー常駐 | 実測状況と技術境界 |
| :--- | :--- | :--- | :--- |
| 常駐メモリ増分 | 複数タブで約 1.2GB 消費 | ホストプロセスで約 45MB 増加 | 重厚なレンダリングエンジンと広告スクリプトを排除 |
| アイドル時 CPU 負荷 | バックグラウンドで 1% から 3% | 完全静止状態で CPU 負荷 0% | 自動ポーリング用タイマーなし |
| 外部通信の発生契機 | タイマーにより常時定期通信 | パネル表示または更新クリック時のみ | モデル推論の通信帯域を阻害しない |
| テーマ配色の追従 | 外部拡張機能による強制変換 | DSH ホストの背景変数と枠線色を継承 | 明色、暗色、ホスト自動追従に対応 |
| プラットフォーム境界 | 一般的なウェブブラウザ全般 | DSH Desktop の Cordis 体系に特化 | 通常の VS Code や Cursor に直接導入不可 |

導入前の注意点です。
本ツールは DSH Desktop の Cordis 拡張機能として構築されています。
VS Code マーケットプレイスの通常拡張ではないため、素の VS Code に直接読み込ませることはできません。
非 DSH 環境で類似の構成を作りたい場合は、UI カード設計と NewsNow API を参考に独自移植する必要があります。
無理な直接インストールは避けてください。

## 3. 実践導入：三段階のサイドバー組み込み手順

DSH Desktop 2.0.18 への導入手順は以下の通りです。

### 1. ターミナルからのパッケージ追加
DSH Desktop を起動します。
メニューから内蔵ターミナルを立ち上げ、標準デスクトップ Profile フォルダへ移動します。

```bash
cd ~/.dsh/profiles/desktop
pnpm add dsh-hot-list@1.3.2
```

GitHub Releases から直接 tgz アーカイブを取得し、絶対パス指定で導入することも可能です。

### 2. 設定ファイルへのバンドル登録
同ディレクトリ内の package.json を開きます。
dsh.profile.bundles 配列の末尾にプラグイン名 dsh-hot-list を追加します。公式の基盤パッケージはそのまま保持してください。

```json
{
  "dsh": {
    "profile": {
      "bundles": [
        "@deepseek-ai/dsh-base",
        "@deepseek-ai/dsh-web-app",
        "dsh-hot-list"
      ]
    }
  }
}
```

JSON の構文に誤りがないか確認し、末尾の不要なカンマを排除します。

### 3. 再起動と動作確認
DSH Desktop を完全に終了して再起動します。
クライアント左端のアクティビティバーにアイコンが表示されます。
クリックしてサイドバーを開きます。
右上の設定アイコンから 19 の情報源を取捨選択できます。初期設定では 14 プラットフォームが有効です。
設定値は DSH のローカルストレージへ保存されます。
即座に利用可能です。

## 4. 完了点検チェックリスト

導入完了後、以下の四項目を確認してください。
1. プロセスメモリの確認：ホストのメモリ増加幅が 50MB 以内に収まっていること。
2. オフライン耐性の検証：ネットワーク切断時にカードをクリックし、白画面にならず過去のキャッシュと再試行ボタンが維持されること。
3. ダークテーマ連携の点検：DSH をダークモードへ切り替え、枠線と背景色が正しく連動すること。
4. アイドル時通信の監視：パケットキャプチャを行い、サイドバー非表示時に外部通信が発生しないこと。作業完了です。
