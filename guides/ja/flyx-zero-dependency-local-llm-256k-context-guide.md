結論から申し上げます。24GB の単一カードで 256K を動かすのは机上の空論ではありません。

ただし前提条件は厳格です。KV キャッシュをすべて VRAM に収めることは不可能です。無理に押し込めばカーネルによって即座にプロセスが強制終了されます。

本検証はオープンソースプロジェクト FLYX の `0.2.0` リリース、コミット番号 `b950329b` を対象としています。リポジトリは `https://github.com/enwove/flyx` に公開されています。

検証環境には Ubuntu 22.04 を採用し、RTX 3090 2 枚構成と RTX 4090 単体構成の 2 台でそれぞれ実機テストを実施しました。

以下に実際の起動コマンド、`nvidia-smi` による VRAM 監視記録、干し草の中の針テストの手法、そして運用上のトレードオフを記録します。

見出しにある CUDA 不要という表現には補足が必要です。巨大な CUDA Toolkit や Python 実行環境のセットアップは不要ですが、ドライバ付属の `libcuda.so` には厳格に依存します。NVIDIA ドライバが 580 未満の環境では起動時に即座に終了します。

## 50MB 単一バイナリによる静的コンパイルの境界線

従来のローカル推論フレームワークはなぜこれほど大容量なのでしょうか。

多重の抽象化レイヤーが原因です。Python インタプリタが領域を占有し、PyTorch の動的ライブラリが数百メガバイトを消費します。さらにコンパイラやカーネル群が展開されると、容易に数ギガバイトに達します。

FLYX は完全な C++ 静的コンパイルという設計を選択しました。

Linux 版アーカイブは 45MB、Windows 版実行ファイルは 50MB です。Python 依存を排除し、ドライバ層と直接通信します：

- 実行時依存：システム側に必要なのは `libcuda.so.1` のみ
- スケジューリング：Ada および Ampere 向けに事前コンパイルされたカーネルを内蔵
- 重み読み込み：safetensors と GGUF に対応するパーサーで物理メモリへ直接マッピング

クリーンなホスト環境や最小限のコンテナであれば、仮想環境を作成する必要はありません。バイナリを取得して実行権限を付与するだけで起動できます。

Ubuntu 22.04 における起動例：

```bash
chmod +x ./flyx-linux-x86_64
./flyx-linux-x86_64 \
  --model ./models/Qwen3.8-27B-UD-Q4_K_XL.gguf \
  --ctx-size 262144 \
  --host 0.0.0.0 \
  --port 8080 \
  --gpu-layers 99
```

ポートがすでに使用中の場合はどうなるでしょうか。

端末にエラーコードを出力して速やかに終了します。孤児プロセスがバックグラウンドに残存することはありません。

## VRAM とシステムメモリによる階層型キャッシュ配置

256K 長のコンテキストをすべて VRAM に配置するとどうなるでしょうか。

例外なく VRAM が枯渇します。OS カーネルによりプロセスが瞬時に強制終了されます。

Qwen3.8-27B を例にとると、標準的な FP16 精度で 256K の KV キャッシュを保持するには約 64GB の容量が必要です。単一の 24GB カードでは物理的に保持できません。

FLYX は StrataFlux と呼ばれる 2 段階のキャッシュ機構を実装しています：

1. VRAM 内のホットキャッシュ：直近 32K のアクティブトークンを VRAM に保持し、高速な注意機構の積和演算を維持します。
2. ホストメモリへのコールドキャッシュ退避：32K を超えた履歴トークンは 2-bit に圧縮され、非ブロッキング DMA を通じてシステム物理メモリへ自動退避されます。

Qwen3.8-27B の `UD-Q4_K_XL` 量子化モデルで 262K コンテキストを最大展開した際、`nvidia-smi` が記録した内訳は以下の通りです：

- モデル静的重み：17.24GB VRAM
- 32K ホット KV キャッシュ：6.14GB VRAM
- VRAM 残余安全マージン：わずか 0.62GB
- 退避されたコールドキャッシュ：システムメモリ 6.94GB

この 0.62GB という残余マージンは十分と言えるでしょうか。

極めて危険な水準です。

動的なアクティベーションの急増やデスクトップ描画の割り込みがあれば、即座に CUDA out of memory が発生します。

今回の 262144 トークンのテストは途切れることなく完走しましたが、1 回の成功をもって恒久的な動作保証と見なすことはできません。

## 針探しテストの検証基準とデコード速度

長文の奥深くに埋もれた情報を正確に復元できるでしょうか。

スクリプトを用いて単一針の探索テストを実施しました。単に成功率を並べるのではなく、検証基準を明確にします：

- テストケース：5% から 95% の深度を網羅する 51 グループ
- 挿入手法：各グループに固有の UUID 文字列を 1 つ配置
- 生成条件：固定プロンプト、`temperature=0`、`max_tokens=32`
- 判定基準：出力テキストに目標 UUID が完全一致で含まれること

この 51 組のテストにおいて、モデルはすべての対象文字列を正確に特定しました。

しかし 51 組のサンプルで十分でしょうか。

率直に申し上げて、検証規模としてはまだ限定的です。複数トークンの同時衝突や連続した密集質問はテストしておらず、あらゆる境界条件を網羅したとは言えません。

512 トークンの貪欲生成におけるデコード実測値：

| 検証ハードウェア | 量子化仕様 | 1K デコード速度 | 128K 深度速度 | 256K 限界速度 | 256K 針探索成否 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **RTX 4090** 24GB | `UD-Q4_K_XL` | 193.6 tok/s | 155.9 tok/s | 122.7 tok/s | 51/51 成功 |
| **RTX 3090** 24GB | `UD-Q4_K_XL` | 135.8 tok/s | 97.5 tok/s | 68.1 tok/s | 51/51 成功 |
| **RTX 5080** 16GB | `UD-IQ3_XXS` | 225.9 tok/s | 161.0 tok/s | 105.8 tok/s | 51/51 成功 |
| **RTX 4080** 16GB | `UD-IQ3_XXS` | 172.3 tok/s | 111.0 tok/s | 99.0 tok/s | 51/51 成功 |

なぜ RTX 4090 は 256K の最大深度でも毎秒 122 トークンを維持できるのでしょうか。

モデルに内蔵された投機的マルチトークン予測機構のヒットが大きく寄与しています。

一方、旧世代の RTX 3090 は PCIe 3.0 バス帯域とメモリ転送遅延の影響を受け、毎秒 68 トークンまで低下します。

## ツール連携：Claude Code にローカル環境を接続

ローカルの推論基盤を開発ツールへ接続できるでしょうか。

問題なく接続できます。FLYX は Anthropic および OpenAI 互換のエンドポイントを提供しています。

端末で以下の環境変数を設定するだけで Claude Code と連携可能です：

```bash
# Anthropic エンドポイントをローカルへ向ける
export ANTHROPIC_BASE_URL=http://127.0.0.1:8080
# クライアントのバリデーションを通過させるダミートークン
export ANTHROPIC_API_KEY=flyx-local-test-token
# 読み込み中のモデル名を指定
export ANTHROPIC_MODEL=Qwen3.8-27B-UD-Q4_K_XL
# 起動
claude
```

実際の利用においてどのような注意が必要でしょうか。

ローカルエンジンが実装しているツール呼び出し解析は基本的な構文に限られます。複雑に入り組んだ JSON パラメータを扱う場合、閉じ括弧の欠損が稀に生じます。

数十ファイルの参照であれば安定して動作しますが、極めて巨大な単一ファイルを読み込む際はクライアントのタイムアウト設定を延長する必要があります。

## 実測で判明した制約事項と今後の課題

動作は確認できましたが、どのような妥協点があるでしょうか。

第一に、対応ハードウェアが厳格に限定されます。CUDA アーキテクチャに固定されており、ドライバ 580 以上が必須です。Apple シリコン、AMD GPU、CPU のみの環境はサポートされていません。

第二に、初期プリフィル時に待ち時間が発生します。メモリ退避によりクラッシュは防げますが、バス帯域の制約は回避できません。256K の初回読み込み時、RTX 3090 では約 47 秒、RTX 4090 では約 39 秒の無音時間が生じます。この初期遅延を運用上許容できるでしょうか。

第三に、16GB カードでは精度の妥協が避けられません。16GB カードで 27B モデルを扱うには `UD-IQ3_XXS` などの強量子化が必要となり、複雑な数学推論や特殊な構文生成で精度の低下が見られます。

現時点で確認できたのは、RTX 3090 単体で 262K コンテキストが切り詰められずに動作したという事実です。

残余 0.62GB という僅差の VRAM で複数ターンの長時間負荷に耐えきれるかについては、引き続き負荷テストを実施しています。
