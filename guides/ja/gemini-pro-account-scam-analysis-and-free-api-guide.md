# Gemini Pro 完成アカウント詐欺の手口分析：停止アカウント転売と正規無料 API ガイド

先週、開発者チャットで Gemini Pro 完成アカウントが 8.4 元で即利用可能というリンクが流れてきました。

掲載されていた証拠スクリーンショットを確認しました。
コンソールで疎通確認できたという十数枚の画像は、タイムスタンプがすべて同日の午後に集中していました。
それを見て確信しました。
同じ午後に十数個のアカウントが揃って開通するわけがありません。
同一マシンかつ同一データセンター IP からバッチ処理で機械的に生成された痕跡です。
自力で疎通確認した開発者なら、十数個分もの同一画像を几帳面に並べるはずがありません。

V2EX のスレッド 1253823 で告発された業者 NiuGe AI が手がけていたのは、まさにこの手口です。
送られてきたパスワードを入力した瞬間、画面に赤文字で「このアカウントは無効になっています」と表示されました。
エラーコードには ACCOUNT_DISABLED とはっきり明記されています。
出品者に問い合わせると、即座に商品画像が返信され、最下部の米粒のような規約文を指差されました。
「当店では問題アカウントの交換や返金は一切受け付けません。」
支払った代金は一瞬で消え去りました。

## 1. 業者が両建てで利益を抜く手口

8.4 元という金額自体は小さくても、この手口の本質は見逃せません。

自動発送の手順を洗い直して気づいたのは、この店舗には最初から在庫が存在しなかったという点です。
上流スクリプトがバッチ登録したメール群は、登録初日に Google 側でフラグが立てられています。
フィンガープリントブラウザで解像度や UA を偽装しても、WebGL の renderer 文字列や Canvas ノイズハッシュの衝突までは隠せません。
出荷される前に、アカウントはすでに凍結されていたのです。
販売されていたのは不良在庫ではなく、死体そのものでした。
原価ゼロのため、売れた分だけ丸儲けになります。

決済が完了するとマニュアルが届き、免責条項が最下段に隠されています。
三者の役割分担は明確です。
マニュアルは購入を促すため、
死体アカウントは納品を装うため、
末尾の小さな規約文は抗議を封じるためです。
巧妙なビジネスではなく、ただの罠に過ぎません。

## 2. 安物の偽物時計と同じ？その論理には納得できません

掲示板でこの件が話題になった際、二千円の偽物ロレックスを買うのと同じで自業自得だという声がありました。
私はそうは思いません。

偽物の時計であっても針は進み、数か月程度なら見た目を繕うことができます。
しかし、この死体アカウントは一度すら動きません。
認証情報を入れた最初の一画面目で ACCOUNT_DISABLED や HTTP 403 Forbidden が返ってきます。
安物買いで失敗するのと、古いマニュアルで釣り上げて最初から機能しない文字列を売りつけるのとでは、根本的に悪質さが異なります。

普段の開発作業でこうした怪しいアカウントに手を出すべきではありません。
過去に手作業を省こうとして試した際、プロキシを三本試し、ゲートウェイを二度再起動し、調査に二時間を費やした末にアカウント自体が死んでいたと判明した苦い経験があります。
本来書くべき実装を放り出して無駄なトラブルシューティングに追われるのは本末転倒です。
自社のプロダクションコードやテストデータを怪しいアカウントに投入すれば、さらなる情報漏洩の危機を招きます。

## 3. なぜバッチ登録アカウントは即座に凍結されるのか

多くの開発者が、なぜ裏業者のアカウントが一日も持たないのか疑問に感じています。
Google のアカウント不正検知ロジックから見ると、自動登録されたバッチ群が初回セッション監査を生き残るのは極めて困難です。

### 登録時のデバイス特徴量クラスタリング
業者はフィンガープリントブラウザやエミュレータで大量登録を仕掛けます。
画面サイズや OS 名を偽装しても、WebGL のグラフィックパイプラインや音声フィンガープリントには強烈な同一特徴が残ります。
同一のデータセンター ASN から短時間に大量登録が押し寄せた場合、バックエンドで一括して高リスク判定が下されます。

### 遠隔ログイン時の行動信頼性欠如
バッチ登録はデータセンターの固定 IP で行われます。
購入者が手元に持ち帰り、家庭用回線や専用 VPN ノードから初回アクセスを試みると、地理的な位置情報が不自然に跳躍します。
アカウントには過去の検索履歴もなければ信頼済み端末の紐付けもありません。
この異常セッションが検知され、即座に電話番号による二段階認証が要求されます。
登録時の一時的な SMS 受信番号はとっくに破棄されているため認証を突破できず、システムによって即座に凍結されます。
API 呼び出しは即時に HTTP 401 Unauthorized や HTTP 403 Forbidden を返します。

## 4. 正規の無料 API を安全に利用するための備忘録

プログラミング支援に Gemini を導入したい場合、正規ルートを利用するのが最も確実です。
怪しい業者を探し回る必要はまったくありません。

### 正規無料枠の仕様と割り当て基準
直接 aistudio.google.com/app/apikey にアクセスし、個人の開発者キーを発行します。
海外のクレジットカードがなくても取得可能です。

無料枠は十分に実用的ですが、Pro モデルが無制限に利用できるわけではありません。
AI Studio のダッシュボードに記載されている制限値はモデルごとに大きく異なります。
日常の開発で主力となるのは Flash 系列です。
例えば gemini-1.5-flash-002 は 15 RPM および一日あたり 1500 RPD が提供されます。
これに対し gemini-1.5-pro-002 の無料枠は厳しく制限されており、長いコンテキストを数回やり取りしただけで上限に到達します。
TPM は一分間あたりのトークン処理速度の指標であり、例えば 1000000 TPM は総量制限ではありません。
この二つを混同すると、コード内でレートリミッターが正常に機能しなくなります。
軽量な埋め込みモデル text-embedding-004 にも十分な無料枠が用意されています。

具体的な数値は必ず自身の管理画面で確認してください。
他人の二次解説記事を鵜呑みにしてはいけません。Google 側は事前通知なしにクォータ規約を変更します。

接続検証は余計なヘッダーを含まないクリーンな curl コマンド一本で完了します。

```bash
curl -s -X POST "https://generativelanguage.googleapis.com/v1beta/models/gemini-1.5-flash:generateContent?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"contents":[{"parts":[{"text":"Hello from local terminal"}]}],"generationConfig":{"maxOutputTokens":8192,"temperature":0.7}}'
```

NextChat、Chatbox、Cherry Studio 等の各種クライアントにも簡単に設定できます。

```json
{
  "provider": "google-ai-studio",
  "base_url": "https://generativelanguage.googleapis.com/v1beta",
  "api_key": "YOUR_GEMINI_API_KEY",
  "model": "gemini-1.5-flash-002",
  "max_output_tokens": 8192,
  "temperature": 0.7,
  "top_p": 0.95
}
```

### 二行の設定で組めるリバースプロキシ
手元の直通ネットワークが不安定な場合、安価な海外 VPS に軽量なリバースプロキシを立てると安定します。
Caddy を使う場合、Caddyfile の中核設定は二行で済みます。

```caddyfile
api.yourdomain.com {
    reverse_proxy https://generativelanguage.googleapis.com {
        header_up Host {upstream_hostport}
    }
}
```

正規に取得した API キーを自身のリバースプロキシ経由で利用すれば、日常の開発作業も安心です。

### チーム調達時の防犯ガイドライン
チームで海外インフラを調達する際は、絶対に個人間の直接送金を行わないでください。
プラットフォームのエスクロー保証こそが唯一の抑止力であり、それを外れるとトラブル時の救済窓口は一切存在しません。

最後に二つの重要事項を添えておきます。
手順書のキャプチャ画像は納品証明になりません。業者のマシンで一度動いただけの記念写真に過ぎないからです。
本番コードや機密テストデータを第三者のアカウントに投入してはなりません。障害発生時にログの確認すら不可能になります。
