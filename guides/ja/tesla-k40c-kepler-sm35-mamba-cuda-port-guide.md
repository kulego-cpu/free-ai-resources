# 二千円台のTesla K40cでMamba-1を動かす：Kepler世代向け手書きCUDAカーネルと順伝播精度検証実録

中古市場を探してみると、13年前に発売されたNVIDIA Tesla K40cが2,000円台で出品されています。安い？信じられないほど格安です。

搭載チップは骨董品レベルです。2013年に登場したKeplerアーキテクチャ、コードネームGK110B。2,880基のCUDAコアを搭載し、PCIe 3.0 x16接続、演算性能はsm_35にとどまります。多くの業者がアルミスクラップとして重量単位で処分しています。こんなカードを買って最新モデルを動かそうとする人間が本当にいるのでしょうか。

しかし、その基板上には正真正銘12GBのGDDR5物理VRAMが実装され、帯域幅は288 GB/sに達します。

主流のAIフレームワークはとっくの昔にサポートを打ち切っています。PyTorchの事前ビルドパッケージはsm_35対応を廃止済みです。FlashAttentionやTritonといった最新の高速化ライブラリも、近年のアーキテクチャが前提です。

Redditのr/LocalLLaMAコミュニティで投稿番号1xr97izのスレッドが話題を集めました。投稿主はコードリポジトリとA100向け比較スクリプトを公開しています。

私たちはそのアプローチを追いかけ、ラボに検証環境を組みました。コードは動きます。ただしFP32の順伝播処理に限られます。速度が遅いのは物理法則ゆえですが、その低レイヤ改造プロセスは実に魅力的です。

## 演算子の世代間断絶：なぜTritonは旧型GPUで動作を拒否するのか

K40c上でTritonに頼るのは不可能です。

Mamba-1の中核となる演算子はSelective Scanです。公式の標準実装は、OpenAI Tritonコンパイラが生成するコードに全面的に依存しています。

nvccで公式コードをビルドしようとすると、端末にPTXターゲットがsm_35をサポートしていない旨のエラーが大量に出力されます。停止。コンパイルは瞬時に頓挫します。

Keplerアーキテクチャには半精度行列演算を行うTensor Coreが一切搭載されていません。bfloat16のような最新フォーマットも、sm_35には対応する物理レジスタ命令が存在しません。公式リポジトリのコードを無理に呼び出せば、カーネル起動失敗のエラーが返るだけです。

公式依存に固執しても意味はありません。

解決策は明快です。Tritonを完全に迂回し、純粋なネイティブCUDA C++でSelective Scanの全演算子を書き直す道を選びました。カーネル内部の計算は単精度浮動小数点FP32レジスタへのフォールバックで処理します。

この自作カーネルはMakefile上でsm_75までターゲットに指定されています。本当に全世代で動くのか？私自身はK40cしか所有していないため、実測はsm_35環境のみで確認しました。MaxwellやPascalの実機は手元にないため、未検証のまま保証することは避けます。

現在、Mamba-1 130Mモデルの順伝播推論は安定して完走します。一方で370Mモデルの長文コンテキスト負荷試験は未実施です。

## 精度検証：順伝播における最大絶対誤差3.8e-06

精度検証は順伝播のみで実施しました。逆伝播は？未実施です。

同一の重みパラメータを用い、乱数シードを42に固定し、入力シーケンス長を512トークンに設定した上で、A100の参照スクリプトとK40cの自作カーネルで各レイヤの出力テンソルを逐次ログ出力しました。

計測された最大絶対誤差は3.8e-06、第19層のSSM状態出力行列で発生しました。

```text
[Layer 01] SSM output max_diff: 1.19e-07
[Layer 08] SSM output max_diff: 8.34e-07
[Layer 15] SSM output max_diff: 2.15e-06
[Layer 19] SSM output max_diff: 3.81e-06
[Layer 24] SSM output max_diff: 3.42e-06
```

逆伝播処理やさらに長いコンテキストでの網羅的検証は未完了であり、性急な結論付けは控えるべきです。

しかし順伝播のデータが示す通り、FP32による内部累積によってParallel Prefix Scanの再帰演算で致命的な浮点桁落ち破綻が防がれていることが確認できます。

Redditの元スレッドはr/LocalLLaMAの1xr97izです。投稿主はリポジトリとレイヤ別比較コードを記載しています。真偽を確かめる際は、二次解説ではなく元投稿のコミットログを直接参照してください。

ここまで厳密に順伝播精度が揃っている点から、自作カーネルのタイルスケジューリングが極めて堅牢に組まれていることが分かります。動いただけでも十分な成果です。

## 実機運用ノウハウ：パッシブ冷却とEPS電源配線の落とし穴対策

ソフトウェアの演算子が通っても、ハードウェア側の物理的な罠が待ち受けています。

最大の難関は排熱です。

Tesla K40cはサーバラック用の専用カードです。工場出荷状態ではアルミ製パッシブヒートシンクしか備えておらず、自前のファンは搭載されていません。安さに惹かれて一般のマザーボードに直挿しすると、通電後わずか3分でコア温度が90度を超え、強制シャットダウンで画面がブラックアウトします。

ダクト改造なしで動かせるか？不可能です。

3Dプリンタ製の専用シュラウドを用意し、後端に9733規格の高静圧シロッコファンを結束バンドで固定します。ファンは必ず独立した12V電源から給電してください。猛烈な風切り音とともに、フル稼働時の温度を65度以下に抑え込めます。

次の難関は電源コネクタです。

K40cの給電ポートはCPU仕様のEPS 8pinとPCIe 6pinの組み合わせです。一般的なPC向けグラフィックボード用の8pinコネクタではありません。電源ユニット付属のGPU用ケーブルを無理に差し込むと、12VとGNDのピン配置が完全に逆であるため、通電しないか最悪の場合は電源回路が焼き切れます。導入前に専用変換ケーブルを必ず手配してください。

ソフトウェア環境はCUDA 11.8ドライバとパッチ適用済みPyTorch 2.7.1の組み合わせが確実です。古いハードウェアには余計なラッパーを排した最小構成のランタイムが最適です。

## コスト計算：2,000円で何が手に入るのか

低レイヤの面白さを語り終えた今、冷厳な計算能力の現実にも触れておきます。

普段使いの推論用カードとして使えるか？その幻想は捨ててください。

13年前の旧世代チップであり、VRAM帯域幅は288 GB/s、行列演算専用ユニットもありません。Mambaモデルを走らせた際の生成速度は非常に低速で、1行のテキストを出力するのに数十秒を要します。対話型インターフェースを動かせば、待ち時間の長さに耐えかねてブラウザを閉じることになるでしょう。

しかし、その真価は速度の追求にはありません。

ゲームソフト1本分の出費で、ネイティブCUDAカーネル開発に対応した12GB大容量VRAM搭載のエンタープライズ級ハードウェアが手に入ります。

状態空間モデルの数理基盤を徹底解剖したい学生にとっても、低予算でオフライン実験環境を構築したい開発者にとっても、格好の実験台として機能します。

限られた予算の中でカーネルのスケジューリングやメモリ配置の勘所を体得する体験は、転売屋に大金を払うことよりもはるかに価値があるのではないでしょうか。
