# 12GB VRAM으로 4-bit MoE를 24 t/s 구동：Betelgeuse 엔진과 듀얼 채널 DMA 실측

로컬 AI를 구축하는 개발자들에게 가장 뼈아픈 한계는 언제나 그래픽 메모리의 부족입니다. 여전히 전 세계 수많은 사용자들이 가성비의 상징인 NVIDIA GeForce RTX 3060 12GB 그래픽카드와 16GB 시스템 메모리를 탑재한 PC를 보유하고 있습니다. 그러나 Qwen 3.8 Flash Next와 같은 차세대 혼합 전문가 모델을 구동하려고 하면 난관에 봉착합니다. 12GB VRAM으로는 전체 전문가 가중치를 적재할 수 없으며, 기존 llama.cpp의 CPU 오프로딩 방식을 사용하면 메모리 스왑으로 인해 초당 0.5에서 0.6토큰 수준으로 시스템이 멈춰 섭니다.

수백억, 수천억 규모의 MoE 모델은 고가의 다중 GPU 환경에서만 실용적이라는 통념이 지배적이던 가운데, 오픈소스 커뮤니티의 Betelgeuse 엔진이 혁신적인 실측 데이터를 증명해 냈습니다.

일반적인 RTX 3060 12GB와 16GB RAM 환경에서 Betelgeuse는 4-bit 양자화 MoE 모델의 생성 속도를 초당 24토큰이라는 쾌적한 수준으로 끌어올렸으며, **전문가 누락 없이 100퍼센트 바이트 단위 정확성을 완벽하게 유지**했습니다.

더욱 놀라운 점은 실측 과정에서 드러난 시스템 병목의 실체입니다. **메모리를 싱글 채널에서 듀얼 채널로 교체한 것만으로 추론 속도가 14 t/s에서 24 t/s로 급상승**했습니다. 이는 단순한 소프트웨어 최적화를 넘어 버스 대역폭의 물리적 한계를 극복한 결과입니다.

## 1. 벤치마크 테스트 환경 및 엔진별 성능 비교

객관적인 성능 평가를 위해 동일한 보급형 하드웨어 플랫폼에서 엄격한 비교 테스트를 진행했습니다：

### 테스트 하드웨어 및 시스템 사양

| 구성 부품 | 세부 사양 |
| :--- | :--- |
| **GPU** | NVIDIA GeForce RTX 3060 12GB VRAM |
| **시스템 메모리** | 16GB DDR4, 단일 16GB 싱글 채널과 8GB 2개 듀얼 채널 비교 |
| **운영체제** | Ubuntu 24.04 LTS 및 최신 NVIDIA 550 독점 드라이버 |
| **대상 모델** | Qwen 3.8 Flash Next, 4-bit 및 8-bit 양자화 버전 |
| **비교 추론 엔진** | llama.cpp 최신 메인라인, Strata 저메모리 모드, Betelgeuse |

### 실제 토큰 생성 속도 비교

동일한 하드웨어 환경에서 양자화 방식과 메모리 채널 구성에 따른 실측 결과는 다음과 같습니다：

| 양자화 규격 및 정밀도 | 메모리 물리 구성 | llama.cpp 결과 | Strata 저메모리 옵션 | Betelgeuse 실측 성능 |
| :--- | :--- | :--- | :--- | :--- |
| **IQ4_XS 4-bit 정밀도** | 16GB 1개 싱글 채널 | 약 0.5 t/s, 극심한 스왑 지연 | 4 ~ 5 t/s | **14.0 t/s** |
| **IQ4_XS 4-bit 정밀도** | 8GB 2개 듀얼 채널 | 약 0.6 t/s, 극심한 스왑 지연 | 5 ~ 6 t/s | **24.0 t/s 쾌적한 실용 속도** |
| **IQ2_XS 극한 양자화** | 16GB 1개 싱글 채널 | 1.47 t/s | 8.11 t/s | **22.03 t/s, 최대 48 t/s 돌파** |
| **Q8_K_XL 8-bit 고정밀** | 16GB 1개 싱글 채널 | 메모리 초과로 구동 불가 | 콜드 8 t/s, 웜 12 t/s | **약 10.0 t/s 안정적 유지** |

Betelgeuse로 측정한 모든 결과는 엄격한 출력 검증을 거쳤으며, 연산 생략 없이 참조 모델과 100퍼센트 바이트 단위로 완벽하게 일치했습니다.

## 2. 메모리 대역폭의 비밀：왜 듀얼 채널 구성 시 속도가 2배가 되는가

위 실측 데이터에서 가장 핵심적인 부분은 16GB라는 총 용량이 동일함에도 불구하고, 싱글 채널에서 듀얼 채널로 구성을 바꾼 것만으로 속도가 14 t/s에서 24 t/s로 70퍼센트 이상 폭증했다는 점입니다.

컴퓨터 구조 관점에서 이는 명확한 물리적 버스 대역폭의 한계 때문입니다：

### 싱글 채널 메모리가 야기하는 전송 병목
MoE 모델 추론 시에는 매 토큰을 생성할 때마다 활성화되는 전문가 계층을 동적으로 교체해야 합니다. 전문가 가중치가 시스템 RAM에 적재되어 있을 경우, 매 단계마다 PCIe 버스를 통해 해당 가중치를 GPU 메모리로 실시간 전송해야 합니다.
- 16GB DDR4 메모리 1개를 사용하는 싱글 채널 모드의 실효 전송 대역폭은 약 19 GB/s에 불과합니다.
- 이 속도는 PCIe 3.0 또는 4.0 인터페이스의 대역폭을 채우지 못하므로, GPU 연산 코어는 가중치 데이터가 도착할 때까지 장시간 유휴 상태로 대기하게 됩니다.

### 듀얼 채널 구성으로 전송 파이프라인 해소
- 8GB 메모리 2개를 장착하여 듀얼 채널을 구성하면 호스트 메모리의 이론상 전송 대역폭이 즉각 38 GB/s 수준으로 2배 증가합니다.
- 메모리 컨트롤러가 2배 빠른 속도로 텐서 가중치를 PCIe 버스에 공급할 수 있게 되어 GPU의 대기 시간이 절반 이하로 줄어듭니다. 메모리 용량을 1MB도 늘리지 않고도 속도가 비약적으로 향상되는 근본적인 원인입니다.

## 3. Betelgeuse 엔진의 핵심 아키텍처 혁신

동일한 오프로딩 환경에서 기존 프레임워크가 심각하게 정체되는 반면, Betelgeuse가 고속 처리를 유지하는 비결은 MoE 작업에 특화된 두 가지 설계에 있습니다：

### 전용 호스트 RAM 희생 캐시
일반적인 메모리 관리 방식에서는 오프로드된 가중치가 운영체제의 파일 캐시와 뒤섞여 불필요한 재할당 지연이 발생합니다. Betelgeuse는 시스템 RAM에 전용 희생 캐시 영역을 고정 할당하여 자주 호출되는 전문가 가중치를 나노초 단위의 지연 시간으로 즉각 처리합니다.

### 하드웨어 비동기 직접 메모리 접근 스케줄링
기존 소프트웨어 전송 방식은 CPU가 직접 개입하여 인터럽트를 발생시키고 데이터 복사를 제어합니다. Betelgeuse는 하드웨어 DMA 채널을 활성화하여 GPU 메모리 컨트롤러가 시스템 RAM에 직접 비동기 데이터 요청을 보냅니다.
GPU가 현재 토큰을 연산하는 동안 다음 단계에서 필요한 전문가 가중치를 백그라운드 DMA 채널을 통해 GPU 스테이징 버퍼로 미리 전송하여 연산과 전송의 완벽한 중첩을 구현했습니다.

## 4. 실전 적용 시 주의점과 한계

정확한 정보 전달을 위해 Betelgeuse 사용 시 유의해야 할 예외 사례와 한계도 투명하게 짚고 넘어가야 합니다：

### 고사양 하드웨어에서의 역전 현상
커뮤니티 테스트 결과 중 하나로, RTX 4080 Super와 64GB RAM을 갖춘 고사양 시스템에서 동일한 Q8 모델을 실행했을 때 속도가 오히려 3.28 t/s로 급감하는 사례가 보고되었습니다.
현재 Betelgeuse 엔진이 Ampere 세대 30 시리즈 아키텍처에 고도로 특화되어 있어, Ada Lovelace 아키텍처나 대용량 메모리 컨트롤러 환경에서는 버스 동기화 지연이 발생할 수 있음을 시사합니다.

### 지원 하드웨어 생태계의 제한
현재 프로젝트는 활발히 개발 중인 단계이며, AMD 라데온의 ROCm 생태계나 8GB 이하의 VRAM을 탑재한 초저사양 환경에 대한 안정화 작업은 아직 진행 중입니다.

## 5. 실전 설치 및 파라미터 구동 가이드

RTX 3060 12GB 환경을 갖추고 직접 성능을 테스트하고자 하는 사용자를 위한 배포 절차입니다：

### 듀얼 채널 메모리 활성화 여부 확인
터미널에서 아래 명령을 실행하여 현재 메모리가 정상적인 듀얼 채널로 작동 중인지 확인합니다：

```bash
# 메모리 슬롯 장착 상태 및 클럭 확인
sudo dmidecode --type memory | grep -E "Locator|Speed|Configured Memory Speed"
```

메인보드 매뉴얼에 명시된 듀얼 채널 권장 슬롯에 메모리가 정확히 장착되어 있어야 최대 성능이 발휘됩니다.

### Betelgeuse 소스 빌드 및 서비스 실행

```bash
# 레포지토리 클론 및 컴파일
git clone https://github.com/zyxciss/betelgeuse.git
cd betelgeuse
make -j$(nproc)

# 핵심 환경변수 설정：하드웨어 비동기 DMA 활성화
export MOE_DMA=1
export HOST_VICTIM_CACHE_MB=12288

./bel-server \
  --model ./qwen3.8-fn-iq4_xs.gguf \
  --n-gpu-layers 33 \
  --ctx-size 8192 \
  --port 8080
```

서버가 구동되면 표준 OpenAI 규격을 지원하는 다양한 클라이언트 도구를 연결하여 실시간 생성 속도를 모니터링할 수 있습니다.
