# 82개 텐서 수정으로 DeepSeek 거부율 제로 달성：검열 해제 버전 실측과 12GB VRAM 마케팅 거품 검증

지난 토요일 새벽 1시、테스트 콘솔 화면이 붉은색 에러로 뒤덮였습니다。

터미널에는 CUDA error during model loading 로그가 찍혔고 샤드 매핑 포인터가 즉각 유실되었습니다。

새로 공개된 DeepSeek-V4.1-Flash 검열 해제 패치를 테스트하던 도중이었습니다。

순정 모델의 안전 가드레일은 결벽증에 가까울 정도로 엄격하여 JailbreakBench 벤치마크 거부율이 85.2퍼센트에 달했습니다。적법한 리버스 엔지니어링 코드조차 입력 즉시 차단되었고、심지어 생각 사슬 내부에서 모델이 스스로 생성을 중단했습니다。보안 취약점 분석을 진행하던 동료들은 막막할 따름이었습니다。

새로 나온 패치는 거부율을 완전히 제로로 만든다고 선언했고、12GB VRAM 그래픽카드 한 장으로 763B 규모의 모델을 구동할 수 있다고 주장했습니다。

하드웨어 세상에 이런 공짜 점심이 정말 존재할까요？

동료와 함께 RTX 4070 12GB 그래픽카드와 128GB 시스템 메모리를 탑재한 워크스테이션을 마련하고 Strata 런타임으로 배포를 시작했습니다。첫 번째 로딩은 메모리 초과로 즉각 다운되었습니다。로그를 확인해 보니 샤드 간 심볼릭 링크가 누락되어 mmap 주소 참조 오류가 발생했습니다。참고로 GPU 레이어 오프로딩 옵션은 Strata에서 완전히 무시됩니다。링크를 수정한 뒤에야 서비스가 간신히 구동되었습니다。

## 1. 아키텍처 역설계：왜 82개 텐서만 건드려도 검열이 해제되는가

먼저 짚고 넘어가야 할 점은 제작자가 방대한 라우터 네트워크를 전혀 건드리지 않았다는 사실입니다。

전체 아키텍처에는 384개의 라우팅 전문가가 존재합니다。제작자는 이 전문가 가중치에 단 1바이트도 손대지 않았으며、기존 GSQ 양자화 정밀도는 온전히 유지되었습니다。

패치 작업은 오직 잔차 스트림 경로상의 정확히 82개 밀집 텐서에 집중되었습니다——어텐션 출력 투영층 attn_output_b、공유 전문가 다운샘플러 ffn_down_shexp、그리고 Engram 키값 계층 engram_wkv 입니다。

왜 이 세 지점만 조정해도 거부 동작이 말끔히 사라질까요？

제 추론은 이렇습니다：안전 정렬 학습 과정에서 형성된 거부 신호는 잔차 스트림 내부에서 매우 뚜렷하게 수렴하는 고차원 활성화 벡터로 전달됩니다。위 세 가지 밀집 투영층은 거부 벡터가 전진 전파될 때 반드시 통과해야 하는 관문입니다。이 관문 파라미터를 살짝 틀어 투영 크기를 임계값 아래로 떨어뜨리면 답변 거부 판단 자체가 성립하지 않게 됩니다。

지식과 추론 역량의 대부분은 384개의 라우팅 전문가가 담당합니다。전문가 네트워크를 건드리지 않았기 때문에 벤치마크 점수 역시 깎이지 않은 것입니다。

이 분석은 텐서 수정 내역을 역추적하여 얻어낸 제 결론이며 공식 릴리스 문서에 설명된 내용이 아닙니다。제작자가 이를 계산하고 의도했다면 탁월한 엔지니어링이고、그렇지 않다면 82개 텐서의 균형점을 우연히 맞춘 행운일 것입니다。

샤드 메타데이터와 바이트 크기가 원본과 완전히 일치하여 수백 기가바이트에 달하는 Engram 색인 테이블을 재계산할 필요가 없었습니다。파일만 교체하여 즉시 구동할 수 있었던 점은 대단히 훌륭합니다。

## 2. 용량 손익 계산：작은 오차로 양자화 선택을 그르치지 말라

제작자는 Strata 환경을 위해 세 가지 양자화 형식을 제공합니다。

로컬 머신에서 실제 파일 용량을 대조해 본 결과 중요한 사실이 드러났습니다。

세 가지 형식 모두 110GB 크기의 공유 Engram 테이블 파일이 필수적으로 추가됩니다。

가장 가벼운 IQ1_M 형식은 평균 1.75 bpw 로 순수 가중치 121GB。

중간 단계 IQ2_XXS 형식은 평균 2.0 bpw 로 순수 가중치 138GB。

상위 단계 IQ2_XS 형식은 평균 2.25 bpw 로 순수 가중치 156GB。

결과적으로 IQ2_XXS 형식을 구동하려면 110GB 메모리 테이블을 합쳐 249GB의 디스크 용량을 반드시 확보해야 합니다。이 계산을 미리 해두지 않고 디스크가 가득 차버리면 누구를 탓하겠습니까？

제작자가 강조한 MMLU-500 점수를 보면 IQ2_XXS 는 82.8퍼센트、IQ2_XS 는 81.6퍼센트로 1.2포인트 차이가 납니다。그러나 500문제 중 1.2포인트는 고작 6문제 차이에 불과합니다。샘플링 온도를 0.1만 바꿔도 6문제 정도는 손쉽게 뒤바뀝니다。평가 오차 범위에 불과한 수치를 잣대로 삼는 것이 과연 합리적일까요？

제가 IQ2_XXS 형식을 선택한 기준은 단 하나였습니다。JailbreakBench 평가에서 생각 사슬 차단 횟수가 3회 연속 완벽한 0회를 기록했기 때문입니다。나머지 두 형식은 1회에서 2회의 차단이 남았습니다。실제 코드 작성 환경에서 체감할 수 있는 지능 차이는 전무했습니다。

## 3. 실측 검증：12GB VRAM 구동 홍보 문구와 실제 지연시간

다음으로 가장 많은 관심을 끈 홍보 문구를 검증해 보겠습니다：12GB 그래픽카드 한 장으로 과연 쾌적하게 돌아갈까요？

테스트 장비는 RTX 4070 12GB 이며 터미널에는 nvidia-smi dmon 과 iostat 를 띄워 실시간 모니터링을 진행했습니다。

공식 실행 명령어는 다음과 같습니다：

```bash
hf download AtomicChat/DeepSeek-V4.1-Flash-1017-Uncensored-GSQ-RCO-GGUF --include "*IQ2_XXS*" --local-dir ds-unc
hf download ISTA-DASLab/DeepSeek-V4.1-Flash-1017-GSQ-RCO-GGUF --include "*Engram*" --local-dir ds-unc
strata launch --model-path ds-unc/DeepSeek-V4.1-Flash-1017-GSQ-RCO-IQ2_XXS-00001-of-00004.gguf
```

결론은 냉정합니다：실행은 되지만 답답할 정도로 느립니다。

12GB 구동 가능이라는 표현은 말장난에 가깝습니다。모델 전체 자산은 249GB 에 달하며 12GB VRAM 에는 한 층의 파라미터도 전부 담지 못합니다。Strata 런타임은 VRAM 을 단순 버퍼로만 활용하고 대부분의 가중치는 128GB 시스템 메모리에 상주시키며、깊은 계층의 전문가와 110GB 색인 테이블은 NVMe SSD 에서 수시로 읽어옵니다。

8K 컨텍스트 환경에서의 실제 측정값：

첫 번째 토큰 생성 지연은 4.2초를 기록했습니다。세 번의 측정에서 편차는 0.3초 미만이었습니다。첫 단어가 나오는 데 4초 이상 걸리는 환경을 일반적인 코드 자동완성에 참고 쓸 수 있는 개발자가 있을까요？

2000줄 분량의 C 드라이버 코드를 컨텍스트에 넣었을 때 토큰 생성 속도는 일상 대화의 초당 18토큰에서 초당 14.6토큰으로 곤두박질쳤습니다。커서 멈춤 현상이 빈번했습니다。

인터넷상에서 구형 카드로 초당 15.5토큰을 기록했다는 글이 있지만 컨텍스트 길이나 배치 크기가 빠져 있습니다。조건이 다른 숫자를 늘어놓고 비교하는 것이 무슨 의미가 있겠습니까？

초당 14토큰은 간단한 잡담용으로는 견딜 만합니다。하지만 처음으로 2000줄 코드 리뷰를 걸었을 때 커서는 30초에 한 번꼴로 넘어갔습니다。커피를 한 잔 타고 돌아왔는데도 터미널은 여전히 글자를 쥐어짜고 있었습니다。이 속도의 모델을 실시간 프로덕션 업무에 붙일 수 있겠습니까？결국 심야 오프라인 배치 처리 전용으로 전환할 수밖에 없었습니다。

## 4. 숨겨진 하드웨어 위협：SSD 수명 소모와 과열 스로틀링

속도 저하보다 훨씬 심각한 문제는 SSD 의 수명 소모와 발열입니다。

모델의 계층 간 특성 검색을 위해 Strata 는 백그라운드에서 시스템 메모리와 SSD 사이의 끊임없는 파라미터 스와핑을 발생시킵니다。

nvme smart-log 도구로 30분간의 고부하 기록을 추적한 결과 누적 기록량이 76GB 급증했습니다。하루 종일 구동할 경우 하루 쓰기량이 3.6TB 에 이릅니다。600TBW 내구성을 지닌 일반 소비자용 SSD 라면 약 166일 만에 수명이 바닥나는 셈입니다。

하루 24시간 내내 풀로드를 돌리는 사람이 과연 존재할까요？

그렇지 않습니다。저 역시 초기에는 수명 단축을 걱정했지만 하루 2시간 정도 테스트하는 수준이라면 몇 년은 너끈히 버팁니다。

정작 저를 무너뜨린 것은 수명이 아니라 온도였습니다。

10분간 연속으로 고속 읽기를 수행하자 SSD 컨트롤러 온도가 74도까지 치솟았습니다。과열 보호 기능이 작동하면서 통신 규격이 PCIe 4.0 에서 강제로 다운그레이드되었습니다。그 순간 토큰 생성 속도는 초당 16토큰에서 초당 9토큰으로 폭락했습니다。새벽에 모델 이상을 의심하며 헤매다 결국 SSD 과열 때문임을 깨달았습니다。새벽 시간에 이런 하드웨어 스로틀링을 겪고 싶을 사람이 누가 있겠습니까？

## 5. 결론 및 현장 엔지니어를 위한 제언

384개의 라우팅 전문가를 온전히 보존한 채 잔차 스트림 경로상의 82개 텐서만을 조율하여 거부율을 제로로 만든 기법은 리버스 엔지니어링 관점에서 대단히 뛰어납니다。

그러나 이를 실제 로컬 환경에서 원활하게 돌릴 수 있는지는 완전히 별개의 문제입니다。

제가 겪은 교훈은 두 가지로 요약됩니다。

첫째：12GB VRAM 이라는 홍보 문구에 현혹되지 마십시오。호스트 머신에 최소 64GB 시스템 메모리를 확보하고 SSD 에는 반드시 강력한 방열판을 장착해야 합니다。쿨링 대책이 없으면 과열로 속도가 반토막 나며 모델이 멈춘 것으로 오해하기 십상입니다。

둘째：양자화 형식은 IQ2_XXS 하나만 기억하십시오。세 가지 형식 중 생각 사슬 거부가 3회 연속 완벽하게 제로였던 버전은 이것뿐이었습니다。속도는 초당 15토큰 안팎이 한계입니다。오프라인 보안 감사에는 유용하지만 실시간 온라인 서비스 연결은 꿈도 꾸지 않는 편이 현명합니다。

이 환경을 로컬에서 쾌적하게 굴려볼 각오가 되셨다면、먼저 SSD 전용 쿨링팬부터 주문해 보는 것은 어떨까요？
