# Agent 추론을 모니터링하며 기술 트렌드 확인하기: DSH Desktop 사이드바 플러그인 DS-NewsTop 아키텍처 및 실측 가이드

로컬 환경에서 긴 호흡의 작업을 실행할 때.
예를 들어 Agent에게 대규모 모듈 리팩토링을 맡기는 상황.
추론에는 보통 2분에서 3분 정도의 대기 시간이 발생합니다.
웹 브라우저를 열어 피드를 확인하다 보면 집중력이 흐트러지기 쉽습니다.
다시 에디터로 돌아왔을 때 검토하려던 코드 맥락을 놓치곤 합니다.
AI 개발 도구 내부에 가벼운 사이드바가 상주한다면 어떨까요.
터미널 로그를 주시하면서 커뮤니티의 기술 이슈를 가볍게 훑어봅니다.
확인이 끝나면 바로 접어둡니다.
메인 코드 작업 영역을 침범하지 않습니다.
쾌적합니다.

오픈소스 플러그인 DS-NewsTop이 이 요구에 부합합니다.
DSH Desktop 환경에 맞춤 설계되었으며 Cordis 모듈식 구조를 통해 다양한 플랫폼의 트렌드를 사이드바에 통합합니다.

## 1. 아키텍처 분석: 동일 출처 프록시와 백그라운드 폴링 배제

개발 환경에 정보 수집 플러그인을 추가할 때 가장 경계해야 할 요소는 무엇일까요.
백그라운드에서 반복 실행되는 무제한 폴링 루프입니다.
상당수 수집 도구는 실시간성을 이유로 수 분마다 수십 개 API에 동시 요청을 보냅니다.
로컬에서 거대언어모델 추론이 진행 중일 때 무분별한 폴링은 CPU 연산 자원과 네트워크 소켓을 잠식합니다.
UI 프레임 드랍을 유발하기도 합니다.

DS-NewsTop의 설계는 매우 절제되어 있습니다.
핵심 구조는 세 계층으로 나뉩니다.

### 1. 호스트 동일 출처 엔드포인트와 인메모리 캐시
사이드바 Webview는 외부 플랫폼과 직접 교차 출처 통신을 하지 않습니다.
플러그인 메인 프로세스 lib/index.js 파일에 단일 내부 엔드포인트를 등록합니다.
`/dsh-hot-list/items?id=sourceID`
프론트엔드는 이 로컬 엔드포인트를 통해서만 데이터를 수신합니다.
호스트 계층에 60초 인메모리 캐시를 내장했습니다.
짧은 시간 내에 패널을 여닫아도 메모리에서 즉시 응답하며 불필요한 외부 패킷을 생성하지 않습니다.
속도가 빠릅니다.

### 2. 업스트림 집약 및 데이터 파싱 경로
데이터 수집 경로는 두 갈래로 나뉩니다.
GitHub, Hacker News, V2EX, Zhihu 등 18개 주요 사이트는 오픈소스 NewsNow 서비스를 경유합니다.
Appinn 커뮤니티 발견 채널의 Markdown 문서는 전용 파서로 처리하여 공지 규칙을 거르고 상위 공유 항목을 추출합니다.
호스트 코드는 요청 대상을 고정하여 프론트엔드가 임의의 외부 URL을 주입하지 못하도록 차단함으로써 프록시 악용을 방지합니다.
보안상 안전합니다.

### 3. 온디맨드 수동 갱신 원칙
이 플러그인에는 자동 주기 폴링 타이머가 존재하지 않습니다.
패널을 열었을 때만 활성화된 카드 목록을 호출합니다.
패널이 닫혀 있는 동안에는 통신을 발생시키지 않습니다.
개별 카드 갱신 또는 전체 갱신 버튼을 눌러야 새로운 데이터를 요청합니다.
수동 갱신 시에는 60초 캐시를 우회하여 최신 데이터를 가져옵니다.
업스트림 서버 응답이 실패하더라도 직전에 가져온 목록을 화면에 유지하고 재시도 버튼을 노출하여 흰 화면 오류를 방지합니다.
안정적입니다.

## 2. 호환성 경계 조건과 실측 자원 소모량

실제 개발 머신에서 3시간 연속 구동 테스트를 진행하며 측정한 지표는 다음과 같습니다.

### 테스트 벤치마크 환경
- 호스트 환경: DSH Desktop 2.0.18, 코어 호환 버전 0.2.1-rc.2 및 0.2.1-rc.3
- 하드웨어 사양: M2 Max 칩 탑재 MacBook Pro, 32GB 통합 메모리
- 플러그인 버전: dsh-hot-list 1.3.2 릴리스

### 실기 구동 성능 비교 장부

| 평가 항목 | 일반 브라우저 다중 탭 확인 | DS-NewsTop 사이드바 상주 | 엔지니어링 분석 및 경계 |
| :--- | :--- | :--- | :--- |
| 상주 메모리 점유 증가분 | 다중 탭 구동 시 약 1.2GB 소모 | 호스트 프로세스 메모리 약 45MB 증가 | 무거운 브라우저 엔진과 추적 스크립트 배제 |
| 유휴 상태 CPU 점유율 | 백그라운드 스크립트로 1%에서 3% 소모 | 완전 정지 상태 유지, CPU 증가분 0% | 자동 폴링 타이머 없음 |
| 외부 네트워크 요청 시점 | 2분 주기 지속적인 백그라운드 요청 | 패널 호출 또는 갱신 버튼 클릭 시만 발생 | 추론 네트워크 대역폭 보호 |
| UI 테마 시각적 동기화 | 외부 확장 프로그램 강제 반전 필요 | DSH 호스트 배경 및 테두리 변수 상속 | 라이트, 다크, 호스트 자동 연동 지원 |
| 에코시스템 지원 범위 | 일반 웹 브라우저 환경 전반 | DSH Desktop의 Cordis 체계에 종속 | 순정 VS Code나 Cursor에 직접 설치 불가 |

기술적 한계를 명확히 짚어야 합니다.
이 도구는 DSH Desktop의 Cordis 플러그인 체계에 맞춰 제작되었습니다.
일반적인 VS Code 마켓플레이스 확장이 아니므로 순정 VS Code에 직접 로드할 수 없습니다.
비 DSH 환경에서 유사한 환경을 구축하려면 카드 UI와 NewsNow API를 참조하여 별도 이식해야 합니다.
호환되지 않는 환경에 무리하게 설치하지 마십시오.

## 3. 실전 배포: 사이드바 연동 3단계 절차

DSH Desktop 2.0.18 환경에 플러그인을 설치하는 과정은 다음과 같습니다.

### 1. 패키지 의존성 설치
DSH Desktop을 실행합니다.
상단 메뉴에서 내장 터미널을 호출한 후 기본 데스크톱 Profile 디렉터리로 이동합니다.

```bash
cd ~/.dsh/profiles/desktop
pnpm add dsh-hot-list@1.3.2
```

GitHub Releases에서 tgz 압축본을 내려받아 절대 경로로 설치할 수도 있습니다.

### 2. 프로필 설정 파일에 번들 등록
해당 디렉터리의 package.json 파일을 엽니다.
dsh.profile.bundles 배열 항목에 dsh-hot-list를 추가합니다. 기존 공식 패키지는 그대로 유지합니다.

```json
{
  "dsh": {
    "profile": {
      "bundles": [
        "@deepseek-ai/dsh-base",
        "@deepseek-ai/dsh-web-app",
        "dsh-hot-list"
      ]
    }
  }
}
```

JSON 문법 오류가 없는지 확인하고 끝부분의 불필요한 쉼표를 제거합니다.

### 3. 재시작 및 동작 검증
DSH Desktop을 완전히 종료한 후 다시 실행합니다.
클라이언트 좌측 활동 바에 핫리스트 아이콘이 나타납니다.
아이콘을 클릭하여 사이드바를 호출합니다.
우측 상단 톱니바퀴 메뉴에서 19개 정보 소스를 필요에 따라 선택할 수 있습니다. 기본값은 14개입니다.
설정값은 DSH 로컬 스토리지에 자동 저장됩니다.
즉시 사용할 수 있습니다.

## 4. 최종 인수 점검 목록

설치 후 다음 네 가지 항목을 점검합니다.
1. 상주 메모리 확인: 호스트 메모리 증가량이 50MB 이내인지 점검합니다.
2. 오프라인 복원력 검증: 네트워크를 끈 상태에서 카드를 클릭했을 때 흰 화면 대신 기존 캐시 목록과 재시도 안내가 유지되는지 확인합니다.
3. 테마 연동 확인: DSH를 다크 모드로 전환했을 때 테두리와 배경색이 즉시 변경되는지 확인합니다.
4. 유휴 네트워크 점검: 패킷 캡처를 통해 사이드바를 닫았을 때 외부 트래픽이 0바이트로 유지되는지 확인합니다. 설정 완료.
