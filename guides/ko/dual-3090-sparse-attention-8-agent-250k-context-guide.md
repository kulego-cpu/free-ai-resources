# RTX 3090 2장으로 250K 에이전트 8개 동시 구동：TokenGate를 뒤집는 전량 희소 어텐션 실전

멀티 에이전트 협업 코딩, 이제는 전혀 낯설지 않습니다.

저희 현장 파이프라인은 보통 5개 에이전트로 역할을 쪼갭니다：설계, 인터페이스 정의, 구현, 단위 테스트, 보안 감사. 워크플로 자체는 짜기 쉽습니다. 하지만 진짜 지옥은 문맥 길이에 있었습니다!

복잡한 레거시 저장소를 통째로 읽히다 보면 250K 토큰은 최소한의 출발선에 불과합니다. 이걸 에이전트 8개가 동시에 물고 돌아간다? KV 캐시만으로 비디오 메모리는 그 자리에서 거덜 납니다!

가진 장비라곤 중고 RTX 3090 2장, 도합 48GB VRAM이 전부입니다. 여기서 일반적인 조밀 어텐션을 무식하게 돌렸다간 8개 세션 메모리 요구량이 수백 GB로 치솟습니다. 데이터센터에 박힌 A100 8장짜리 랙도 단숨에 뻗어버릴 수준입니다!

## 왜 TokenGate 같은 가지치기는 에이전트 환경에서 박살 나는가

초기 연산을 아끼겠다고 TokenGate처럼 점수 낮은 토큰을 연산 중에 쳐내라는 조언도 있습니다. 메모리는 아끼겠지요. 정말 그걸로 해결될까요?

단발성 질의응답이라면 모를까, 여러 턴을 주고받으며 반성하고 고쳐나가는 에이전트 루프에 집어넣는 순간 대참사가 벌어집니다!

잘 생각해 보세요. 첫 턴에서 에이전트가 쓸데없다고 판단해 버린 함수 선언이나 타입 수식어가, 바로 세 번째 턴에서 숨은 버그를 추적할 때 유일하게 필요한 단서일 수 있습니다. 밑바닥 레이어에서 한번 잘려 나가면 이후 아무리 프롬프트를 쏟아부어도 회상률은 완전 0으로 추락합니다. 이건 속도 개선이 아닙니다. 인위적으로 기억상실증을 유발한 것에 불과합니다!

## 전량 보존과 동적 스케치로 뚫어낸 현장 해법

저희는 정반대로 뒤집었습니다：토큰은 단 한 개도 버리지 않는다. KV 캐시 전체를 시스템 메모리에 두고, GPU 메모리에는 초소형 요약 스케치만 남긴다.

구조는 세 단계로 맞물립니다：

첫 번째. 전체 문맥의 KV 캐시는 호스트의 128GB DDR4 메모리에 4비트 패킹 형태로 보존합니다. 비디오 메모리에는 긴 과거 기록을 절대 상주시키지 않습니다.

두 번째. GPU 메모리에는 각 토큰당 랭크 64짜리 초소형 키 스케치 Key Sketch 만 남겨둡니다. 매 디코딩 스텝마다 커스텀 Triton 커널을 돌려 250K 토큰 중 가장 중요한 상위 2000개 토큰, 전체의 약 1퍼센트만 GPU 내부에서 빠르게 추려냅니다.

세 번째. 스케치에 걸려든 1퍼센트 조각만 PCIe 4.0 버스를 통해 VRAM으로 넘겨 표준 연산 코어로 밀어 넣습니다. 전송량은 수십 GB에서 매 스텝 고작 십여 MB 수준으로 급감합니다.

PCIe 버스가 막히지 않느냐고요? 홍보 문구가 아니라 P99 지연 시간을 보셔야 합니다. 대역폭 병목이 풀리니 디코딩 속도는 아주 안정적으로 유지됩니다.

## 날것 그대로의 트러블슈팅：CUDA Graph 붕괴와 메모리 계산식

이번 튜닝, 처음부터 순탄했던 건 절대 아닙니다. 첫 테스트 때 아주 화끈하게 터져 나갔습니다!

패치한 vLLM 환경에서 CUDA Graph capture를 때리는 순간, 터미널에 kernel shape mismatch 에러가 뿜어져 나오더니 Triton 컴파일러가 데드락에 걸려 프로세스 전체가 먹통이 되었습니다.

생성된 중간 어셈블리를 뒤지며 두 시간을 꼬박 날리고서야 원인을 잡았습니다：동적 슬라이스 텐서가 128바이트 경계를 넘어갈 때 메모리 정렬 패딩이 빠져 있었습니다. 1단계 필터링 top-k를 4096에서 2000으로 낮추고 메모리 풀에서 128바이트 정렬을 강제하고 나서야 그래프 캡처에 파란불이 들어왔습니다!

메모리 소모량은 감으로 때려 맞히는 게 아닙니다. 전부 수식으로 나옵니다：

32개 레이어, 8개 KV 헤드, 128차원으로 계산해 보세요. 오프로딩 없이 단일 250K 세션을 fp16으로 돌리면 캐시만으로 64GB에 육박하고 3090 두 장은 순식간에 OOM으로 강제 종료됩니다.

4비트 형태로 시스템 RAM에 보존하도록 바꾼 결과, 8개 동시 세션이 128GB 시스템 메모리에서 차지하는 건 약 64GB에 불과합니다. 비디오 메모리 안에는 모델 본체와 1퍼센트 동적 조각만 남아 RTX 3090 VRAM 소모량은 21.8GB 선에서 굳건히 버텼습니다. 이렇게 메모리 사형 선고를 피했습니다.

## 솔직히 인정해야 할 한계：4비트 드리프트와 복합 추론 검증 부족

커뮤니티 개발자들이 날려준 비판은 전적으로 맞습니다：4비트 KV의 누적 오차는 절대 가볍게 넘길 문제가 아닙니다!

긴 복합 코드 리팩터링 도중 변수 수식어 하나라도 삐끗하면 만들어낸 패치는 치명적인 구멍이 됩니다. RULER나 LongBench 같은 긴 문맥 복합 추론 벤치마크는 아직 전수 조사를 마치지 못했습니다. 이 한계는 솔직하게 먼저 인정하고 들어갑니다.

그러니 이 실험적 구성을 금융 결제 시스템 같은 미션 크리티컬 프로덕션에 무턱대고 꽂아 넣지는 마세요!

로컬에서 직접 검증해 보시려면 아래 구동 명령어로 시작하시길 권합니다：

```bash
python3 -m vllm.entrypoints.openai.api_server \
  --model Qwen/Qwen2.5-Coder-32B-Instruct \
  --tensor-parallel-size 2 \
  --max-model-len 262144 \
  --gpu-memory-utilization 0.92 \
  --enable-chunked-prefill \
  --sparse-kv-sketch-dim 64 \
  --sparse-top-k 2000
```
