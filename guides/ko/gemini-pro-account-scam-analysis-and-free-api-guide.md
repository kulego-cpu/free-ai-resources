# Gemini Pro 완성형 계정 사기 수법 해부: 비활성화 계정 재판매와 정식 무료 API 가이드

지난주 개발자 단톡방에 Gemini Pro 완성형 계정을 8.4 위안에 즉시 쓸 수 있다는 링크가 올라왔습니다.

첨부된 콘솔 성공 캡처 화면을 직접 확인해 보았습니다.
콘솔에서 호출 성공을 증명한다는 십여 장의 스크린샷은 타임스탬프가 모두 같은 날 오후에 몰려 있었습니다.
그걸 본 순간 바로 견적이 나왔습니다.
한 사람이 같은 날 오후에 십여 개 계정을 일일이 테스트해서 뚫었을 리 없습니다.
단일 머신과 동일한 데이터센터 IP 대역에서 스크립트로 대량 찍어낸 흔적이었습니다.
진짜 직접 뚫은 개발자라면 십여 개 계정의 증명 스크린샷을 똑같이 남겨둘 이유가 없습니다.

V2EX 게시글 1253823 에서 폭로된 판매자 NiuGe AI 가 벌인 일이 바로 이 수법입니다.
전달받은 비밀번호를 입력하자마자 첫 화면에 빨간 글씨가 떴습니다. 이 계정은 사용 중지되었습니다.
에러 코드에는 ACCOUNT_DISABLED 라고 선명하게 적혀 있었습니다.
판매자에게 항의하자 즉시 상품 상세 이미지를 보내오며 맨 아래 쌀알만 한 안내 문구를 짚었습니다.
본 매장은 문제 계정에 대한 환불이나 교환을 일절 진행하지 않습니다.
결제한 돈은 그대로 허공으로 사라졌습니다.

## 1. 판매자가 양쪽에서 마진을 챙기는 구조

8.4 위안이라는 액수 자체는 크지 않더라도 그 뒤에 숨은 구조는 명확히 짚어야 합니다.

자동 발송 흐름을 찬찬히 뜯어보고 나서야 깨달았습니다. 이 상점에는 애초에 재고라는 게 없었습니다.
상위 스크립트가 대량 생성한 이메일 풀은 생성 당일 구글 보안망에 이미 마킹되었습니다.
지문 브라우저로 해상도와 UA 값을 속여도 WebGL 렌더러 문자열과 Canvas 노이즈 해시 충돌까지 감출 수는 없습니다.
계정은 구매자에게 전달되기 전에 이미 동결 상태였습니다.
판매자는 불량 재고를 파는 것이 아니라 이미 죽은 시체를 팔고 있었습니다.
원가가 0원이니 파는 족족 전부 순이익이 됩니다.

결제가 완료되면 사용 가이드가 발송되고 면책 조항은 가장 아래쪽에 숨겨둡니다.
세 가지 요소의 역할 분담은 명확합니다.
가이드는 결제를 유도하고,
죽은 계정은 배송을 위장하며,
맨 밑의 작은 문구는 항의를 입막음합니다.
고도화된 기술이 아니라 전형적인 덫일 뿐입니다.

## 2. 짝퉁 시계와 비교? 그 논리에는 동의할 수 없습니다

원글이 공개된 후 댓글창에서 이만 원짜리 짝퉁 시계를 산 것과 마찬가지라며 구매자 욕심 탓이라는 의견이 있었습니다.
저는 동의하지 않습니다.

가짜 시계라도 바늘은 돌아가며 서너 달은 겉모습이라도 흉내 낼 수 있습니다.
하지만 이 죽은 계정은 단 한 번도 작동하지 않습니다.
비밀번호를 입력하는 첫 단계부터 ACCOUNT_DISABLED 혹은 HTTP 403 Forbidden 이 뜹니다.
싼 맛에 가짜를 사는 것과 이미 죽어버린 인증 정보를 오래된 가이드로 낚아 파는 사기 행위는 본질적으로 다릅니다.

실제 개발 업무에서 이런 계정은 절대 건드리지 마십시오.
예전에 테스트 목적으로 한 번 샀다가 프록시 세 개를 갈아치우고 게이트웨이를 두 번 재부팅하며 두 시간 동안 원인을 찾았는데 알고 보니 계정 자체가 죽어 있었습니다.
본격적인 비즈니스 로직을 개발해야 할 황금 같은 시간에 헛수고를 하는 것은 너무 큰 낭비입니다.
회사 코드나 테스트 데이터를 이런 출처 불명의 계정에 전송하면 치명적인 보안 사고로 이어집니다.

## 3. 대량 생성 계정이 출고 즉시 정지되는 이유

많은 개발자들이 왜 암시장 계정이 하루도 버티지 못하는지 의아해합니다.
구글 계정 위험 감지 시스템 관점에서 볼 때 자동 생성 배치 계정은 첫 세션 검증을 통과하기가 사실상 불가능합니다.

### 생성 단계 기기 식별 특징 클러스터링
전문 작업장은 지문 브라우저나 에뮬레이터로 대량 가입을 진행합니다.
화면 해상도나 운영체제 명칭을 바꾸더라도 WebGL 그래픽 파이프라인과 오디오 지문에서 강한 동일 특징이 남습니다.
동일한 데이터센터 ASN 대역에서 짧은 시간 동안 가입 요청이 집중되면 백엔드에서 즉시 고위험군으로 일괄 마킹합니다.

### 이기종 로그인 시 행동 신뢰도 결여
대량 생성은 데이터센터 고정 IP 에서 수행됩니다.
구매자가 계정을 넘겨받아 가정용 인터넷이나 일반 상용 VPN 노드에서 처음 접속하면 위치 정보가 급격하게 도약합니다.
해당 계정에는 검색 기록이나 신뢰할 수 있는 기기 연결 내역이 전무합니다.
이 비정상 세션은 즉시 보안 시스템을 작동시켜 SMS 인증을 요구합니다.
가입 당시 사용한 임시 가상 번호는 이미 만료되었으므로 인증을 넘지 못하고 계정이 즉각 동결됩니다.
이 상태에서 API 를 호출하면 HTTP 401 Unauthorized 또는 HTTP 403 Forbidden 에러가 반환됩니다.

## 4. 정식 무료 API 를 안전하게 연동하는 실무 메모

개발 보조 목적으로 Gemini 를 도입하려면 정식 경로를 이용하는 것이 가장 확실합니다.
불법 계정 쓰레기통을 뒤질 이유가 전혀 없습니다.

### 정식 무료 티어와 쿼터 기준
공식 콘솔 aistudio.google.com/app/apikey 에 접속하여 개인 개발자 키를 발급받으십시오.
해외 신용카드 없이도 바로 발급받을 수 있습니다.

무료 티어는 꽤 넉넉하지만 Pro 모델을 무제한으로 쓸 수 있는 것은 아닙니다.
AI Studio 대시보드의 할당량 안내를 보면 모델별 분당 요청 한도가 큰 차이를 보입니다.
일상적인 코딩 보조의 핵심은 Flash 계열입니다.
예를 들어 gemini-1.5-flash-002 모델은 분당 15 회인 15 RPM 과 하루 1500 RPD 를 제공합니다.
반면 gemini-1.5-pro-002 모델의 무료 할당량은 훨씬 엄격하여 긴 컨텍스트를 몇 번 주고받으면 금방 한계에 도달합니다.
TPM 은 1000000 TPM 처럼 분당 토큰 처리 속도 지표이며 총량 상한선이 아닙니다.
이 두 개념을 혼동하면 클라이언트 측 레이트 리미터가 엉뚱하게 동작하게 됩니다.
경량 텍스트 임베딩 모델 text-embedding-004 역시 무료 할당량이 충분히 주어집니다.

구체적인 수치는 반드시 본인의 관리자 콘솔에서 직접 확인하십시오.
구글은 사전 공지 없이 정책을 조정하므로 2차 가공 블로그 글만 맹신해서는 안 됩니다.

인증 테스트는 불필요한 헤더 없이 깔끔한 curl 명령 한 줄로 충분합니다.

```bash
curl -s -X POST "https://generativelanguage.googleapis.com/v1beta/models/gemini-1.5-flash:generateContent?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"contents":[{"parts":[{"text":"Hello from local terminal"}]}],"generationConfig":{"maxOutputTokens":8192,"temperature":0.7}}'
```

NextChat, Chatbox, Cherry Studio 같은 클라이언트 설정창에도 간편하게 등록할 수 있습니다.

```json
{
  "provider": "google-ai-studio",
  "base_url": "https://generativelanguage.googleapis.com/v1beta",
  "api_key": "YOUR_GEMINI_API_KEY",
  "model": "gemini-1.5-flash-002",
  "max_output_tokens": 8192,
  "temperature": 0.7,
  "top_p": 0.95
}
```

### 두 줄 설정으로 구축하는 리버스 프록시
로컬 직결 네트워크가 불안정하다면 저렴한 해외 VPS 에 리버스 프록시를 구성하면 해결됩니다.
Caddy 기준으로 Caddyfile 핵심 설정은 단 두 줄이면 끝납니다.

```caddyfile
api.yourdomain.com {
    reverse_proxy https://generativelanguage.googleapis.com {
        header_up Host {upstream_hostport}
    }
}
```

정식 발급받은 API 키를 개인 프록시 도메인으로 경유하면 안정적인 개발 환경이 완성됩니다.

### 팀 구매 시 필수 방어선
팀 차원에서 해외 인프라를 도입해야 한다면 개인 간 직접 계좌 이체는 절대 피하십시오.
플랫폼 에스크로 결제만이 유일한 보호 장치이며, 플랫폼을 벗어나는 순간 문제 발생 시 분쟁 해결 창구가 완전히 사라집니다.

마지막으로 두 가지만 당부드립니다.
튜토리얼 캡처 화면은 배송 증빙이 아닙니다. 판매자 로컬 환경에서 단 한 번 돌아갔던 기념사진에 불과합니다.
프로덕션 소스 코드나 핵심 테스트 데이터를 외부 계정에 전달하지 마십시오. 사고 발생 시 에러 로그조차 조회할 수 없습니다.
