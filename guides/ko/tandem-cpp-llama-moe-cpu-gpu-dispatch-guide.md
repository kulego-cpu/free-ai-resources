# 독점 포맷의 한계를 넘어：tandem.cpp로 모든 범용 MoE 추론 속도를 3.3배 끌어올리는 배포 가이드

로컬 하드웨어에서 개인용 AI 워크스테이션을 구축하는 개발자들에게 전문가 혼합 Mixture of Experts 아키텍처는 언제나 깊은 애증의 대상이었습니다.

장점은 명확합니다. 총 매개변수 수는 수백억에서 천억 개를 넘나들며 최상위 거대 모델에 준하는 추론 역량을 발휘하지만, 매 토큰을 생성할 때는 극히 일부분의 전문가 가중치만 활성화하므로 이론적인 연산량은 매우 낮습니다. 그러나 실제 환경에서는 양자화를 적용해도 40GB에서 80GB에 육박하는 파일 크기 탓에 24GB VRAM을 갖춘 플래그십 그래픽카드 한 장에 온전히 적재할 수 없다는 물리적 장벽에 부딪힙니다.

그동안 개발자들은 두 가지 답답한 타협안 사이에서 고민해야 했습니다.
기존 llama.cpp의 시스템 메모리 오프로딩 방식을 택하여 PCIe 버스의 반복적인 전송 병목으로 인해 초당 20에서 30토큰 수준의 답답한 속도를 감수하거나,
혹은 특정 독점 파일 포맷만을 강제하며 내부적으로 비활성 전문가를 무단 생략하여 수치를 부풀리는 폐쇄적인 가속 엔진에 의존하는 것이었습니다.

오늘 공개된 독립 오픈소스 프로젝트 tandem.cpp는 이러한 타협의 고리를 완전히 끊어냈습니다.

순수 llama.cpp 위에 직접 적용되는 가벼운 패치 세트로 제작되어 별도의 가중치 변환 과정이 전혀 필요 없으며, 오픈소스 커뮤니티의 모든 표준 GGUF 모델을 온전히 구동할 수 있습니다. 더욱이 수식적 근사나 편법을 완전히 배제한 상태에서 단일 GPU 환경의 디코딩 처리량을 3.3배 수준으로 단숨에 끌어올렸습니다.

## 1. 기존 오프로딩 방식과 독점 솔루션의 구조적 한계

tandem.cpp의 기술적 혁신을 이해하기 위해서는 현재 로컬 MoE 추론을 가로막고 있는 두 가지 병목을 직시해야 합니다.

### 버스 전송 대역폭의 물리적 한계
전통적인 메모리 오프로딩은 시스템 램을 단순한 보관함으로 취급합니다. 그래픽카드 메모리에 다 들어가지 못하는 레이어는 시스템 메모리에 배치되고, 라우팅 게이트웨이가 메모리에 있는 전문가를 호출할 때마다 PCIe 버스를 통해 GPU로 가중치를 실시간 복사합니다. 하지만 PCIe 4.0 x16 기준 이론적 대역폭 한계로 인해 매 토큰마다 수백 메가바이트의 텐서를 전송받느라 GPU의 막강한 연산 코어는 대부분의 시간을 데이터 대기 상태로 허비하게 됩니다.

### 독점 포맷 종속과 모델 지능 훼손
이를 해결하고자 등장한 일부 엔진들은 모델 구조를 변형한 폐쇄적인 전용 포맷을 요구했습니다. 더 큰 문제는 벤치마크 점수를 과장하기 위해 중요도가 낮은 전문가의 연산을 무단으로 생략하는 편법을 기본 활성화했다는 점입니다. 우리가 어제 정량적으로 분석했듯 이러한 인위적 왜곡은 모델의 논리적 사고력을 치명적으로 퇴화시킵니다.

## 2. tandem.cpp의 핵심 접근법：진정한 이종 협업 연산

tandem.cpp의 설계 철학은 매우 정직합니다. **근사 계산을 거부하고, 독점 규격을 강제하지 않으며, 각 하드웨어가 제 역할을 다하도록 분동하는 것**입니다.

단일 사용자 텍스트 생성은 메모리 대역폭과 지연 시간에 매우 민감한 작업입니다. 시스템 램에 있는 가중치를 굳이 GPU로 옮겨서 버스를 막히게 할 바에는, 시스템에서 대기 중인 고성능 멀티코어 CPU가 그 자리에서 직접 전문가 행렬 연산을 수행하도록 만드는 것이 훨씬 효율적이라는 발상입니다.

이 협업 구조는 두 가지 핵심 기둥으로 지탱됩니다.

- **고빈도 전문가의 그래픽 메모리 고정**：라우팅 과정에서 가장 자주 호출되는 핵심 전문가들을 GPU VRAM에 상주시켜 테라바이트급 초고속 대역폭을 온전히 활용합니다.
- **멀티코어 CPU와의 실시간 동시 연산**：호출 빈도가 낮은 메모리 상주 전문가가 선택되면 버스를 통한 가중치 이동을 발생시키지 않고 호스트 CPU로 직접 연산 작업을 분배합니다. GPU와 CPU가 각자의 작업을 마친 후 호스트 측에서 결과를 즉시 병합함으로써 버스 병목을 완벽하게 우회합니다.

특히 제작자는 다음과 같은 단호한 엔지니어링 원칙을 천명했습니다.
**tandem.cpp는 하위 전문가 생략을 절대 하지 않으며, 캐시 가중치를 편애하는 왜곡 라우팅을 사용하지 않고, 탐욕 디코딩을 강제하지도 않습니다. 모든 토큰 생성 결과는 원본 llama.cpp와 수학적으로 완전히 일치합니다.**

## 3. 실측 성능 비교：가감 없는 벤치마크 지표

실제 하드웨어 환경에서 이 협업 구조가 얼마나 강력한 성능 개선을 보여주는지 커뮤니티의 실측 데이터를 통해 증명되었습니다.

### 테스트 하드웨어 환경
- **프로세서**：Intel Core i5-12400F 6코어 12스레드
- **시스템 메모리**：64GB DDR4 듀얼채널
- **그래픽카드**：NVIDIA GeForce RTX 4090 24GB VRAM
- **벤치마크 항목**：GSM8K 수학적 추론 디코딩 토큰 속도

### 디코딩 처리량 비교표

| 모델 규격 및 양자화 등급 | 원본 llama.cpp | tandem.cpp 협업 | Strata 정밀 모드 | 원본 대비 향상 배율 |
| :--- | :--- | :--- | :--- | :--- |
| **Qwen 3.8 Flash Next IQ3_S 탐욕** | 29.8 t/s | **97.3 t/s** | 103.6 t/s | **3.27배** |
| **Qwen 3.8 Flash Next 기본 무작위 샘플링** | 29.4 t/s | **96.1 t/s** | 98.1 t/s | **3.27배** |
| **gpt-oss-120b 초대형 모델 탐욕** | 27.8 t/s | **51.5 t/s** | 범용 GGUF 미지원 | **1.85배** |
| **gpt-oss-120b 초대형 모델 권장 설정** | 27.7 t/s | **48.0 t/s** | 범용 GGUF 미지원 | **1.73배** |
| **긴 문맥 64k 프롬프트 Prefill 단계** | 기준선 | **1.4배에서 1.8배 빠름** | — | **첫 응답 지연 단축** |

이 외에도 GLM-4.5-Air, Qwen 3.6 35B A3B, DeepSeek V4.1 등 다양한 희소 MoE 모델에서 1.4배에서 2.1배에 달하는 안정적인 속도 개선이 확인되었습니다.

수치가 입증하는 결론은 명확합니다.
순수 llama.cpp 대비 3배 이상의 극적인 도약을 이루어내면서도, 폐쇄적 포맷을 요구하는 Strata 정밀 모드 수준의 성능을 범용 GGUF 모델 그대로 구현해냈다는 점이 이번 프로젝트의 독보적인 강점입니다.

## 4. 커뮤니티 토론과 기술적 세부 고찰

프로젝트 릴리스 이후 기술 포럼에서 깊이 있는 토론이 이어졌으며 중요한 사실들이 정리되었습니다.

### llama.cpp 공식 캐시 패치와의 차이점
공식 저장소에 제출된 캐시 패치와의 본질적 차이는 **능동적 이종 협업과 수동적 대기의 차이**에 있습니다. 기존 캐시 구현은 여전히 GPU만을 바라보며 캐시 미스 발생 시 대기 상태에 빠지지만, tandem.cpp는 쉬고 있던 멀티코어 CPU 자원을 실질적인 연산 주체로 적극 활용합니다.

### 시스템 메모리 대역폭의 영향
하드웨어 구성에 따른 성능 차이도 검증되었습니다.
- 대역폭이 제한된 16GB 메모리 환경에서도 56.9 t/s라는 준수한 속도를 기록했습니다.
- 고대역폭 DDR5 듀얼채널이나 쿼드채널 이상의 워크스테이션 환경을 갖추면 CPU 측의 연산과 메모리 전송 속도가 더욱 빨라져 더 높은 처리량을 기대할 수 있습니다.

### 속도와 신뢰성의 균형점
일부 도구가 자랑하는 127 t/s 수준의 수치는 하위 전문가 생략이라는 근사 처리가 들어간 결과입니다. 코드 생성이나 수학적 분석처럼 단 하나의 오류도 허용되지 않는 정밀한 업무 환경에서는 97.3 t/s의 무손실 정확성을 제공하는 tandem.cpp가 가장 정직하고 확실한 선택입니다.

## 5. 실전 가이드：빌드 및 실행 방법

tandem.cpp는 GitHub github.com/ewhacc/tandem.cpp 저장소에 깔끔한 패치 형태로 제공됩니다. 빌드와 적용 과정은 매우 직관적입니다.

### 소스코드 클론 및 패치 적용
공식 llama.cpp를 내려받고 tandem.cpp 패치를 적용합니다.

```bash
git clone https://github.com/ggml-org/llama.cpp
cd llama.cpp
git clone https://github.com/ewhacc/tandem.cpp /tmp/tandem
git apply /tmp/tandem/patches/*.patch
```

### CMake 빌드 수행
CUDA 가속을 켜고 호스트 프로세서에 최적화하여 컴파일합니다.

```bash
cmake -B build -DGGML_CUDA=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release -j
```

### 범용 MoE 모델 실행
기존에 다운로드해 둔 표준 GGUF 모델을 그대로 지정하여 실행합니다.

```bash
./build/bin/llama-cli -m ./models/qwen3.8-flash-next-iq3_s.gguf -p "파이썬으로 고성능 동시성 스크래퍼를 작성해줘" -n 512
```

## 6. 시스템 아키텍트의 총평：개방형 생태계와 정직한 엔지니어링

더 빠른 연산 속도를 얻기 위해 사용자들을 독점 규격에 가두거나 모델의 지능을 깎아 먹는 꼼수는 언제나 유혹적입니다. 그러나 오픈소스 생태계를 지탱하는 진정한 힘은 보편적인 개방성과 연산의 정직함에서 비롯됩니다.

tandem.cpp는 하드웨어 아키텍처에 대한 깊은 이해와 정교한 스케줄링을 통해, **모델의 본래 지능을 1비트도 훼손하지 않고 범용 포맷의 자유를 지키면서도 엄청난 성능 향상을 이뤄낼 수 있음**을 증명했습니다.

소비자용 단일 그래픽카드로 최신 MoE 모델을 한계까지 몰아붙이고자 하는 모든 엔지니어에게 오늘 가장 든든한 기술적 무기가 되어줄 것입니다.
