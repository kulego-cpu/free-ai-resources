让 Claude Code 跑完一整套单测，中间通常要等上一两分钟。

这段空当最尴尬。坐在工位前干瞪眼很无聊。去沙发上躺会儿或者倒杯水，单测万一挂了，想追问一句哪条断言没过，难道又得起身跑回电脑前重新敲键盘？

我之前试过远程桌面。在六寸手机屏幕上双指缩放，在虚拟触控板上拖小箭头找终端窗口，两分钟就劝退了。我也试过手机端新开独立 Claude 对话。更难受。新会话根本没有刚才的代码上下文。你问它第二条报错怎么修？它反问你刚才跑了什么命令、项目长什么样。为了追问一句话，还得把半屏终端日志从电脑复制到手机上。

前两天在 V2EX 分享创造节点看到开源扩展 liliangshan.claude-code-config-helper，适配 VS Code v1.95+ 与 Node.js v20.18 环境。它在底层拉起一个轻量安全中继服务。桌面端依托 Claude CLI v0.2.14 运行任务。手机端通过网络直接连入相同的会话通道。

离开键盘以后，同一段会话到底能不能接得上？真拿它改业务代码，手机端到底适合做什么？我拿一个正在重构套餐周期的真实项目测了一整天。

## 手机当遥控器：接力会话的真实边界

手机在这套流程里不是编辑器，就是个遥控器。别在六寸屏上敲路径，真不行。

它能干三件事：看单测红绿，给一句修正方向，发现跑偏就喊停。回工位再拉 diff，确认了再提交。

拿一个真实的日期计算用例来说：某个会员权益需要在月末赠送体验期。测试卡在了 packages/billing/src/services/subscription.ts 里面的 2027-01-31 日期断言上。

如果人在工位前，很可能会顺口交代一句帮我修一下这个报错。大模型遇到这种提示词，为了让用例变绿，大概率会直接去改测试用例里的预期值。

换成手机接力工作流，节奏完全变了：

```text
工位电脑前下达约束指令
"npm test -- test/unit/expiry.spec.ts -t subscription-expiry
只跑套餐到期单测，列出第一条失败用例的输入与实际值，先不改文件"
    │
    ▼
移步沙发，手机浏览器接收断言
输入 2027-01-31T23:59:59Z，预期输出遇到 2027-02-28 的月份边界断崖
    │
    ▼
手机端补全业务判定裁决
"先告诉我实现和测试各自按哪种规则算，不要为了让它变绿就改预期值"
    │
    ▼
返回工位查看双屏 Diff
检查修改是否顺手破坏了其他季卡逻辑，确认无误执行 git commit
```

在沙发上躺着的时候，这句不要为了让它变绿就改预期值直接进了工位电脑上的 Claude Code 会话。手机端不需要复制粘贴上下文，电脑端也不会盲目破坏测试代码。这种指令把控与大屏审查的分工，节奏很顺。

## 网络拓扑配置与三步接入实践

手机要连进来，第一件事是搞清网络拓扑到底怎么走，千万别在地址绑定上栽跟头。

如果直接把中继服务绑在 127.0.0.1 会怎样？手机就算连在同一个 Wi-Fi 里也敲不进去。回环地址只接受本机流量。

怎么连进来？通常有两种选法：一种是改绑局域网地址 0.0.0.0 并配合 authKey 口令；另一种是走扩展自带的工作区中继通道，双端同时建立加密 WebSocket 握手。

源码在 GitHub 仓库 `liliangshan/claude-code-config-helper` 开源。具体接入只需三步：

### 第一步：在桌面端调通本地环境

在 VS Code 插件市场搜索扩展 ID liliangshan.claude-code-config-helper，确认发布者为 liliangshan。本地需要已安装 Node.js 与 Claude CLI 工具链。

安装后打开侧边栏的 LLS CCAI 图标，按引导选择本地安装的 Claude CLI 路径，并填入你自己拥有的模型提供商 API Key。

在桌面插件输入框随便发一句测试指令，确保能正常吐出文字。这步确保本地运行环境健全。

### 第二步：授权绑定当前工作区

在 VS Code 里打开你正在开发的工程目录。

点击聊天输入框下方的远程办公按钮。注册登录一个工作区识别账号，并将当前打开的代码文件夹授权绑定到该节点下：

```json
// 若采用局域网直连，需改绑局域网地址并设置随机认证令牌
{
  "remoteBridge.bindHost": "0.0.0.0",
  "remoteBridge.port": 9120,
  "remoteBridge.authKey": "CUSTOM_LOCAL_TOKEN_HEX",
  "remoteBridge.workspace": "current-project-root"
}
```

建议第一次先拿一个测试仓库做验证。看清手机发出的消息到底进了哪个终端。

### 第三步：手机浏览器直接接入

用手机自带浏览器打开中继地址或局域网 IP 如 192.168.1.120:9120，登录相同的工作区识别账号或输入预设令牌。

页面里会列出当前在线的电脑名称、项目路径以及活动会话列表。点击主工作区，第一句话可以发个只读探测：

```text
想理解这个项目的套餐计算逻辑，我应该先读哪个文件？先不要改代码。
```

抬头看一眼电脑屏幕，你会看到同一行文字同步打在桌面端 VS Code 的终端里。随后模型的推理过程和建议文件路径，同步流式推回手机端屏幕。整个交互没有额外的转发延迟。

## 会话切分策略：主会话与只读审计的分工

真正在手机端多聊几句，你会发现它提供了主工作区与并行任务两个不同入口。

这两个入口怎么选？选错了会怎样？容易把上下文搞混。

原则很简单：凡是带刚才、继续、第二条这种上下文指代的追问，必须死守主会话。

比如电脑上刚跑完单测输出了三条失败信息，你在手机端想追问第二条报错是不是同一个原因引发的？这句话只能发给主会话。因为只有主会话保留着上一轮跑测试的真实退出码与报错堆栈。如果手快切到了并行会话发这句追问，新会话根本不知道第二条指的是什么。

那么并行会话适合干什么？适合做完全独立的只读排查。

主会话改代码，旁路只读。别让两边同时碰 `subscription.ts`。真撞上了，`git diff` 里全是互相覆盖，你连哪版是基线都说不清。我一般让旁路只干一件事：

```text
检查当前项目里还有哪些地方把一个月写成了固定的三十天？只列出文件名和行号，先不要修改任何文件。
```

两边面对的是同一套磁盘代码，但彼此的上下文窗口互不干扰。主任务负责写，旁路任务负责查。

## 现场实测踩坑：四条必须留心的工程细节

这套工具很轻便，但用手机远程操控工位电脑写代码，有几个极易翻车的暗坑必须提前防备。

### 坑一：合盖睡眠与休眠掉线

手机只是遥控器，跑任务的大脑依然留在工位电脑上。

有一次我把指令发出去，人去茶水间接了杯水，掏出手机发现界面显示项目离线。回工位才发现，因为五分钟没动鼠标，MacBook 自动合盖熄屏休眠了，VS Code 的后台网络连接全部断开。

真要离开工位用手机接力，电脑不能合盖睡眠。系统设置里的息屏策略要调整好，或者在终端敲一行 caffeinate -dimsu -t 7200 强制锁定两小时防休眠。这招很管用。

### 坑二：手机上的停止按钮不是撤销键

在手机端看到 Claude Code 改代码改偏了，界面上有个红色的停止按钮。

点了停止，很多新手以为代码会自动回退到修改前。根本不是这样。

停止按钮的作用等同于向进程发送 SIGINT 信号。它只能截断大模型后续的 Token 流与 Tool Call 调度。如果它在前一步已经把错误逻辑写入磁盘文件，那几行坏代码依然留在当前工作区里。回到电脑前第一件事，依然是执行 git status 与 git diff --stat HEAD~1 检查脏改动。

### 坑三：不可在手机端盲目确认提交与部署

当测试全绿的信息推到手机屏幕上时，人往往有一种想立刻让它提代码发版的冲动。

千万别这么干。测试全部通过，只能说明现有的几十条单测断言没报错，完全无法替你检查出多余的文件变动。

大模型写代码经常顺手多改动几行不相干的格式，甚至误删重要的注释。确认下一步查哪里可以在手机上做，但只要涉及批量文件修改、数据库迁移脚本、或者 Git Commit 与 Push，必须老老实实坐回大屏前仔细看一遍。

### 坑四：工作区账号与模型服务 Key 的概念混淆

刚上手时很多同行会遇到找不到绑定的电脑。

排查一圈往往发现，手机端登录的设备账号，与 ~/.claude/config.json 里的 ANTHROPIC_API_KEY 搞混了。工作区账号只负责 9120 端口的设备路由匹配。它完全不附带模型额度。推理调用始终依赖本地 settings.json 配置的服务商凭证。两者职责完全独立。

## 落地建议与技术收摊

把手机拉进开发工作流，到底是不是伪需求？

如果你指望抱着手机把一个几十万行的庞大系统从头写到尾，那绝对是自讨苦吃。手机永远无法替代多显示器、机械键盘与完整的终端排错环境。

回到工位就看 diff。手机上别做提交，别跑迁移，别 push。测试全绿也不等于干净，模型经常顺手改格式、删注释，得你自己扫一遍。手机只适合回一句：“先别改，告诉我实现和测试各自按哪种规则算。”

让大模型跑一轮费时的测试，你完全可以起身倒杯咖啡，躺在沙发上扫一眼失败的断言，顺手回一句指正方向的业务判定。两个场景切清楚，日常编码体验确实能少受不少罪。
