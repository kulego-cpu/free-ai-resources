# 边跑 Agent 边看热榜：DSH Desktop 侧边栏插件 DS-NewsTop 架构拆解与部署实测

在本地跑长任务。
比如让 Agent 重构某个底层模块。
模型推理往往需要等待两三分钟。
切回主浏览器看新闻？
常常刷着刷着就分了心。
等回过神来，早忘了刚才要审查的代码分支到底改了哪几个函数。
我一直在想，能不能在 AI 客户端内部挂一个轻量侧边栏？
边盯终端控制台的调用栈，边扫两眼社区讨论。
看完随手折叠起来，不占主视窗空间。

开源插件 DS-NewsTop 正好给出了这种工程解法。
它专为 DSH Desktop 打造。
通过 Cordis 模块化扩展机制，把全网聚合热点嵌进客户端左侧活动栏。

## 一、 架构拆解：同源代理与零后台轮询权衡

我给 DSH 装这个插件之前，先去看了一眼它有没有 timer 定时器。

原因很现实。
去年我装过一个类似的热榜扩展，90 秒一次 fetch，十几个源并发拉取。
当时我正在跑 7B 模型的量化推理，风扇直接起飞。
后来我养成习惯，凡是带实时两个字的扩展，先翻源码找 setInterval。

DS-NewsTop 源码里没有这个东西。
它是打开面板才发请求，关掉就彻底不发了。
这一点直接决定了我会不会把它长期挂在活动栏里。

请求路径也做了收敛。前端只打宿主同源接口：
`/dsh-hot-list/items?id=sourceID`
前端只向这个本地端口要数据。
宿主层拿着固定的上游列表去取。
上游地址在宿主代码里是写死的常量，前端传什么参数进来都没用。
这一层我原本没太在意，直到想起来 SSRF 攻击面：
如果接口能接受任意 URL 呢？
那它就是个免费的开放代理，用不了多久就会有人拿它扫内网。

60 秒内存缓存是顺手捞的便宜。
反复开关面板不会每次都打外网，点开即有。

上游数据源分为两条主线：
一条是通过开源聚合服务 NewsNow 获取知乎、V2EX、GitHub、Hacker News、少数派等 18 个主流平台榜单；
另一条是针对小众软件发现频道 Markdown 页面做专门解析。
代码过滤掉置顶规则帖，按顺序截取前十条内容分享。

如果上游服务返回 502 错误，界面会保留上一轮成功抓取的内容，并给出重试按钮。
我第一次遇到 NewsNow 节点抖动的时候还挺意外的，以为要白屏，结果旧列表还在，没干扰我干活。

## 二、 兼容边界与硬件开销实测

跑了三个小时，内存有没有漏？
CPU 占用高不高？
内存和 CPU 我都是拿活动监视器看的，没有更细的分析手段，所以下面这些数字也就是个量级参考。

### 测试平台基准
- 宿主环境：DSH Desktop 2.0.18，底层核心兼容版本 0.2.1-rc.2 与 0.2.1-rc.3
- 硬件平台：MacBook Pro 配 M2 Max 芯片，32GB 统一内存
- 插件版本：dsh-hot-list 1.3.2 稳定版

### 实机运行表现与资源记录

内存方面，冷启动后稳定在增加 40 到 50MB 区间。
跑三个小时，没有明显爬升的迹象。
对照那次我开了七个新闻网页标签，在 Chrome 128 下活动监视器显示约 1.1 到 1.3GB 内存占用。
但这个对比不太严密，标签数量多少、有没有开浏览器休眠差别很大，只能做个大概参考。

CPU 方面，采样窗口里这个进程的读数一直是 0.0，我没有看到跳变。
但 0.0 不等于绝对的零，只是低于活动监视器的分辨率。
我能确定的是它没有拉起可见的后台活动，跑了一下午，机器风扇一直没响。

| 评测维度与场景 | 传统浏览器多标签对照 | DS-NewsTop 侧边栏常驻 | 实测观察与边界说明 |
| :--- | :--- | :--- | :--- |
| 常驻内存增量 | 约 1.1GB 至 1.3GB | 宿主内存增加约 45MB | 不加载完整浏览器多进程与广告脚本 |
| 空闲状态 CPU 表现 | 页面脚本偶发 1% 读数 | 活动监视器读数基本贴着 0.0 | 低于监测分辨率，未见异常波峰 |
| 外部网络请求时机 | 定时器后台持续通信 | 仅在面板呼出或点击刷新时请求 | 按需请求，不占用推理带宽 |
| 界面主题视觉自适应 | 依靠外部插件强行反色 | 自动继承 DSH 宿主背景与边框变量 | 支持白天、黑夜及宿主自动跟随 |
| 生态系统适配边界 | 适用于各种网页浏览器 | 强绑定于 DSH 桌面端 Cordis 体系 | 无法直接装进原生 VS Code 或 Cursor |

需要说明的是，这项工具完全围绕 DSH Desktop 的 Cordis 插件体系构建。
它不是通用的 VS Code 市场扩展，无法直接在纯净版 VS Code 中运行。
非 DSH 用户如果需要类似体验，只能参考其前端卡片布局与 NewsNow 接口设计进行二次移植，别在标准编辑器里强行折腾。

## 三、 实操部署：三步完成侧边栏集成

在 DSH Desktop 2.0.18 中配置插件，具体执行步骤如下：

### 1. 终端安装依赖包
打开 DSH Desktop，在顶部菜单中调出内置终端，进入默认桌面 Profile 目录：

```bash
cd ~/.dsh/profiles/desktop
pnpm add dsh-hot-list@1.3.2
```

也可以直接从 GitHub Releases 下载对应的 tgz 压缩包，通过绝对路径进行离线安装。

### 2. 注册插件模块至配置清单
编辑当前 Profile 目录下的 package.json 文件。
找到 dsh.profile.bundles 数组字段，追加插件名称 dsh-hot-list，注意保留原有官方基础依赖：

```json
{
  "dsh": {
    "profile": {
      "bundles": [
        "@deepseek-ai/dsh-base",
        "@deepseek-ai/dsh-web-app",
        "dsh-hot-list"
      ]
    }
  }
}
```

检查 JSON 语法合法性，避免多余逗号破坏格式。
这步坑过不少人，漏掉花括号或者多了逗号会导致桌面端 profile 无法正常加载。

### 3. 重启验证与验收核对
彻底退出并重启 DSH Desktop。
在客户端左侧活动栏中，即可看到每日热榜图标。
点击进入侧边栏面板，右上角齿轮图标支持按需勾选 19 个数据源，默认勾选 14 个。
选定后偏好配置直接保存在 DSH 本地存储中。

## 四、 验收检查清单

按以下四项确认运行状态：
- 观察本地进程内存：检查宿主内存增量，正常情况下在 50MB 上下波动。
- 验证离线回退：断开外网，点击已加载卡片，确认界面保留历史列表并展示重试入口，没有直接报错退回到空白。
- 检查主题联动：切换全局深色模式，确认卡片边框、背景与文字色值跟随宿主变化。
- 确认无自动心跳：静止状态下观察网络抓包，面板收起时对外请求始终为零。
