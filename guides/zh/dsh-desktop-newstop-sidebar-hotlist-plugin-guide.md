## 一、 架构拆解：同源代理与零后台轮询权衡

给开发工具加资讯插件，最怕什么？
最怕后台死循环轮询。
很多聚合扩展为了追求所谓实时性，每隔两分钟抓一次全网十几个接口，十几家网站轮着请求。
如果本地还在跑代码推理，这种无脑轮询会直接抢占网络与 CPU 资源。
甚至卡死前台界面。

DS-NewsTop 在架构设计上相当克制。
核心逻辑分为三层：

### 1. 宿主同源接口与内存缓存
侧边栏界面不直接向第三方平台发起跨域请求。
插件主进程在宿主内注册了统一接口：
`/dsh-hot-list/items?id=sourceID`
前端只向本地同源接口要数据。
宿主层内置了 60 秒内存缓存机制。
短时间内重复打开面板，直接命中内存，绝不向外网发送多余请求。
速度极快。

### 2. 上游聚合与解析通道
数据源分为两条主线：
一条是通过开源聚合服务 NewsNow 获取知乎、V2EX、GitHub、Hacker News、少数派等 18 个主流平台榜单；
另一条是针对小众软件发现频道 Markdown 页面做专门解析。
代码过滤掉置顶规则帖，按顺序截取前十条内容分享。
宿主代码死锁请求目标，不接受前端传入自定义上游网址，避开接口沦为任意外链代理的风险。
安全可靠。

### 3. 克制的主动刷新设计
插件去掉了任何定时自动轮询计时器。
打开面板时按需加载已启用的卡片。
不打开就不发请求。
日常更新依靠单卡刷新按钮或全量刷新按钮触发。
手动刷新会绕过插件自身的 60 秒缓存，强制向上游发起查询。
如果上游服务返回失败，界面会保留上一轮内容，并给出重试按钮，不至于白屏崩溃。
稳当。

## 三、 实操部署：三步完成侧边栏集成

在 DSH Desktop 2.0.18 中配置插件，具体执行步骤如下：

### 1. 终端安装依赖包
打开 DSH Desktop。
在顶部菜单中调出内置终端，进入默认桌面 Profile 目录：

```bash
cd ~/.dsh/profiles/desktop
pnpm add dsh-hot-list@1.3.2
```

也可以直接从 GitHub Releases 下载对应的 tgz 压缩包，通过绝对路径进行离线安装。

### 2. 注册插件模块至配置清单
编辑当前 Profile 目录下的 package.json 文件。
找到 dsh.profile.bundles 数组字段，追加插件名称 dsh-hot-list，注意保留原有官方基础依赖：

```json
{
  "dsh": {
    "profile": {
      "bundles": [
        "@deepseek-ai/dsh-base",
        "@deepseek-ai/dsh-web-app",
        "dsh-hot-list"
      ]
    }
  }
}
```

检查 JSON 语法合法性，避免多余逗号破坏格式。

### 3. 重启验证与验收核对
彻底退出并重启 DSH Desktop。
在客户端左侧活动栏中，即可看到每日热榜图标。
点击进入侧边栏面板。
右上角齿轮图标支持按需勾选 19 个数据源，默认勾选 14 个。
选定后偏好配置直接保存在 DSH 本地存储中。
即开即用。

## 四、 验收检查清单

完成部署后，按以下四项检查确认运行状态：
1. 观察本地进程内存：检查宿主内存增量，正常情况下增幅在 50MB 以内。
2. 验证离线回退：断开外网，点击已加载卡片。界面应保留历史列表，并展示重试入口，不能白屏。
3. 检查主题联动：切换全局暗色模式。卡片边框、背景与文字色值应即时生效。
4. 确认无自动心跳：静止状态下观察网络抓包。面板未呼出时，对外请求应始终为零。收工。
