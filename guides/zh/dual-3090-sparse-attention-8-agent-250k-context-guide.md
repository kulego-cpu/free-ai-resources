# 双卡 3090 并发 8 个 250K 智能体：反 TokenGate 的全量稀疏注意力实战

多智能体协同写代码，现在真不稀奇。

流水线很好搭。我们拆了五个 agent：架构、接口、实现、单测、审计。各司其职。麻烦全在上下文！

重构一个复杂项目，代码加依赖，250K 只是起步价。8 个 agent 一起并发？显存当场吃穿！

两张 3090，显存总共 48G。如果跑原生全稠密？8 个会话直接奔着几百 G 狂飙。机房里的 A100 八卡集群都得跪下！

## 为什么 TokenGate 剪枝在智能体场景会翻车

有人说用 TokenGate 这类前向剪枝。打分低的 token 当场扔掉，省显存，行不行？

单轮简单问答确实能应付。但到了多轮深度协同的智能体场景，直接当场翻车！

你想想看。第一轮随手扔掉的函数签名，第三轮查 bug 正好要用。底层一旦切除，后续怎么发问？召回率直接归零！这哪是加速？分明是人为失忆！

## 全量留存加动态速写的实际解法

我们反着来：token 一个不丢，KV 缓存全量放系统内存，显存内只留极小特征速写。

整体架构由三层逻辑拼接：

第一步。KV 全量留在 128G 宿主内存。压成 4-bit 紧凑排布。显存坚决不常驻全量历史。省出空间。

第二步。显存只留秩 64 的极小特征速写 Key Sketch。每步解码用 Triton 算子粗筛。从 250K 里挑出 top 2000。只占百分之一。

第三步。命中的百分之一词元走 PCIe 4.0 搬进显存。交给计算核心。传输体量每步只要十几兆。总线稳住了。

PCIe 到底卡不卡？看 P99 延迟，不看口号。通道带宽压力解除后，解码流畅度才能稳住。

## 真实踩坑记录：CUDA Graph 崩溃与显存算式

这次调优真没那么顺畅。第一次上线直接当场炸裂！

打完补丁跑 CUDA Graph capture。终端直接报错：kernel shape mismatch。Triton 编译死锁。整个进程挂了。

排查整整两小时。翻汇编才发现问题：张量跨越 128 字节边界没做对齐填充。我们把 top-k 从 4096 压到 2000。并在内存池强制 128 字节对齐。捕获流程这才绿灯跑通。

算一笔账：32 层、8 个 KV 头、128 维。不做分层卸载，单条 250K 的 fp16 就要吃掉将近 64GB。两张卡瞬间 OOM 崩溃。

改用 4-bit 驻留内存。8 条并发在 128G 宿主内存里只占约 64G。显存只留权重与 1% 动态切片。显存稳在 21.8G。死刑线守住了。
