# Natively 3.0 搭配 Ollama 本地会议助理实测：断网转写、硬件开销与本地 MCP 权限边界

上周五下午三点，技术评审会。

## 一、 云端会议助手的威胁模型与本地隔离思路

开会用云端纪要软件，数据到底怎么走的？
拆开抓包看，无非三步：
先通过浏览器扩展或虚拟驱动抓取麦克风与扬声器音频流；
再把分片音频打包上传到公有云对象存储；
最后云端模型吐出纪要文本，回传到屏幕。

问题出在哪里？
原始音频落在了别人的磁盘上。
存储桶配置一漏，或者接口鉴权出偏差，底价、架构和内部争论全成了明文。
想保住商业秘密，最彻底的办法就是不给它联网权限。

Natively 3.0 的架构很直接：
音频采集、语音转写、模型总结和历史检索，全压在单机内网。
所有网络请求死锁在 127.0.0.1 回环地址。
一个字节的音频也不往外发。

## 二、 架构拆解：全离线运行的三大底层组件

拔掉网线，单台电脑怎么撑住连续两小时录音？
底层靠三块拼图搭起来：

### 1. 基于 Rust 的双轨原生音频分流
网页端抓音频很容易爆音丢采样。
Natively 底层直接用 Rust 写音频捕获管道。
一路通过系统底层核心音频接口抓扬声器，记录参会同事发言；
另一路独立抓本地硬件麦克风，记录自己发言。
两条音轨物理隔离。
扬声器放出的声音，绝不会倒灌进麦克风音轨搞混发言人。

### 2. 端侧 Whisper 与 Parakeet 语音转写引擎
切片音频直接喂给端侧模型，不碰外网。
苹果芯片走 CoreML 与 Metal 图形管线加速；
Windows 平台走 DirectML 接口。
端到端转文字延迟压在 450 至 600 毫秒。
本地跑转写，不用买云端按分钟计费的语音时长。

### 3. Ollama 模型后端与本地 MCP 服务
转写出的实时文本流，持续推给本地跑着的 Ollama 进程。
大模型可以选 Qwen2.5 7B，也可以换成轻量级 Llama3.2 3B。
在 3.0 版本里，它还在本地回环网络挂了一个轻量 MCP 服务器。
终端里的其他本地代码工具，能不能直接查会议纪要？
能。
敲一条命令，直接调阅上周会议敲定的接口定义。

## 三、 实机测试：45 分钟会议的资源账与局限

全本地跑模型，硬件撑得住吗？
先看资源账。测试机是 M2 Max 配 32GB 统一内存，Whisper large-v3-turbo 端侧量化，Ollama 跑 Qwen2.5 7B 指令微调版。
45 分钟、五人、双轨音频，峰值内存到 22GB，风扇明显提速，SoC 在 85 度左右。
16GB 机器不建议并发跑转写和 7B 摘要；8GB 直接别试。
延迟和摘要耗时见下表，但样本只有五轮，不是严格基准测试。

| 评测维度与场景 | 传统商业云端会议工具 | Natively 3.0 本地离线链 | 工程状态与边界说明 |
| :--- | :--- | :--- | :--- |
| 音频外发流量 | 每小时数百兆音频直传公网 | 零字节外发，仅限本机进程通信 | 物理切断第三方存储泄密链路 |
| 语音转文字延迟 | 约 800 毫秒至 1.5 秒波动 | 约 450 毫秒至 600 毫秒 | 本地 Rust 管道无网络往返耗时 |
| 全文摘要生成耗时 | 云端集群处理约 4 秒完成 | 本地 7B 模型生成耗时 8 秒 | 本地算力受限，速度落后于云端集群 |
| 宿主机系统内存峰值 | 桌面客户端占用约 450MB | 宿主机总内存占用达到 22GB | Whisper 与端侧模型并发常驻代价 |
| 长时间运行散热负载 | 机身微温，风扇转速平稳 | 机身发热显著，SoC 接近 85 度 | 持续高负荷运算不可避免的产热 |

本地方案有纯粹的离线优势，也有明明白白的物理代价。
视频会议本身就在吃图形编解码。
本地 Whisper 还在一秒不停地啃音频切片。
后台 Ollama 还要常驻显存算向量。
三项叠加，内存直接吃掉 22GB。
如果手头机器只有 16GB 内存，并发跑这套工作流，大概率会触发严重的虚拟内存交换。

## 四、 踩坑复盘与安全防护边界

两天高频测试下来，有几个坑需要提前避开：

### 1. 麦克风独占模式引发的录音丢失
刚装好那会，同事说话转写很顺，我自己说的话却在记录里失踪。
排查发现，视频会议客户端把麦克风硬件设备锁死了。
怎么解决？
进设置面板，把音频捕获从直接监听麦克风，切换成系统级音频混音输入管道。

### 2. 长时间会议上下文退化
会议开过半小时之后，文本越积越多，模型推理会不会变慢？
会。
如果不加限制，7B 模型推理生成速度会从每秒 40 字掉到 10 字。
解决办法是把上下文滑动窗口锁定在 8192 token 以内。
每隔一段时间分段归纳一次，别让模型硬吃整场会议的原始长文本。

### 3. 本地 MCP 服务的攻击暴露面
MCP 这块我比较在意。3.0 会在本地回环网络起一个轻量 MCP 服务器。目前我没看到细粒度鉴权或只读隔离：知道端口的本地进程可以查询纪要；如果本机跑了不可信 Agent 脚本，理论上也能改或删历史记录。等官方加权限开关前，别把这个端口接给外部流水线，也别把监听地址改成 0.0.0.0。

### 4. 商业赞助链接提醒
代码仓库 README 顶部放着第三方录制 API 的推广链接。
工具本身开源可用，但大家配环境时要盯紧设置项。
认准本地部署的 127.0.0.1 端口，不要误勾选外部云端服务。

## 五、 实操配置与验收检查清单

动手搭这套环境，按下面步骤来：

### 1. 启动本地 Ollama 服务
先装好 Ollama，终端里拉取推理稳定的模型：

```bash
ollama run qwen2.5:7b
```

### 2. 安装桌面端工具
macOS 环境通过 Homebrew 安装客户端：

```bash
brew install --cask Natively-AI-assistant/tap/natively
```

### 3. 配置纯离线环境
打开客户端设置项：
- 模型提供商选 Ollama，地址填本地回环端口 11434。
- 语音识别选本地 Whisper 引擎，初次使用会自动下载端侧权重。
- 关掉云端同步开关，确认界面显示离线状态。

### 4. 离线验收与端口安全核验
断 Wi-Fi，飞行模式录一段。字幕能滚出来，待办列表能生成，文件留在本机。代价是 22GB 内存和一阵风扇声。就这样。终端里敲 `lsof -i :11434` 确认 Ollama 只监听 127.0.0.1；检查 MCP 端口未对局域网暴露；确认转写文件落在本地 SQLite 库。收工。
