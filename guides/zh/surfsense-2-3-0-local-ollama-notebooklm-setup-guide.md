# 彻底断网也能跑的 NotebookLM：SurfSense 2.3.0 直连本地 Ollama 实操实录

昨天下午四点，财务同事拿着一份外包结算表找过来。

两百多行数据、跨了三个工作表、表里嵌满了复杂的嵌套公式。

同事想找工具排查逻辑漏洞。但他指着右下角的水印发愁：谁敢真把带公章的采购合同或者未公开财报往第三方云端服务器里扔？

谷歌 NotebookLM 的交叉检索确实好用。但数据只要离开发送端，在严格的审计眼里就是板上钉钉的泄漏事故。

我们把目光投向了刚更新的开源项目 SurfSense 2.3.0。

官方宣传这是平替 NotebookLM 的本地化方案。代码基于 Apache-2.0 协议全开源。它不仅能挂接本地 Ollama 模型做问答，还内置了能直接修改 Word 与 Excel 的文档 Agent。

我们搬出机房那台测试机。机器配了 RTX 4070 12GB 显卡与 32GB 内存。拔掉外网网关。只留局域网。现场开启断网实测。

## 1. 容器通信与上下文暗坑：第一脚踩进去直接报错

按照经验，我们首先在测试机上拉取了 SurfSense 2.3.0 的单容器镜像。

新版最大的进步在于架构收敛。它把所有依赖打包进了一个镜像里。不需要再配置独立的 Postgres 数据库和 Redis 队列。仅挂载一个本地数据目录就能跑。

官方给出的基础启动命令如下：

```bash
docker run -d \
  --name surfsense \
  -p 3000:3000 \
  -v /opt/surfsense/data:/data \
  ghcr.io/modsetter/surfsense:latest
```

容器很快启动成功。浏览器打开后台。添加模型供应商时，我首先在地址栏敲入 `http://localhost:11434/v1`。

点击测试连接，终端界面当场弹红：Connection refused。

连不上是应该的。容器里的 localhost 就是容器自己内部的网络栈，跟宿主机根本不是一码事。

宿主机上的 Ollama 默认只监听 127.0.0.1 环回地址。在启动服务前必须导出环境变量：

```bash
export OLLAMA_HOST=0.0.0.0
ollama serve
```

换成穿透域名 `http://host.docker.internal:11434/v1` 再点测试——界面再次弹红：dial tcp: lookup host.docker.internal: no such host。

这又是什么报错？

机房这台测试机装的是 Ubuntu 22.04 裸机系统。底层跑的是原生 Docker 守护进程；`host.docker.internal` 这个域名只在 Windows 和 Mac 的桌面版环境预置。在原生 Linux 底下，Docker 根本认不出这个名字。这不就抓瞎了吗？

原启动命令必须手动补上一行宿主网关映射：

```bash
docker run -d \
  --name surfsense \
  --add-host=host.docker.internal:host-gateway \
  -p 3000:3000 \
  -v /opt/surfsense/data:/data \
  ghcr.io/modsetter/surfsense:latest
```

删掉旧容器重新启动。再次点击测试连接。绿色的连接成功标记终于亮起。

顺手在终端里打了一行验证：

```bash
curl http://host.docker.internal:11434/v1/models
```

屏幕吐出完整的模型列表。通信彻底跑通。

但更要命的暗坑还在后面。

当我把一份八十页的 PDF 招标技术文件丢进知识库，并尝试启动 Agent 模式自动提取核心指标时，后台日志狂刷报错：Context window exceeded。模型直接僵死。光标停留原地纹丝不动。

排查到这里，你能怪模型太笨吗？

根本不是模型的问题。Ollama 默认分配的上下文窗口往往只有 4096 个 token。文档 Agent 既要吃进几万字的技术规范，还要在前面垫上长长的函数调用提示词。默认才给 4096，塞几万字规范进去，Agent 第一步就撑爆了。

必须针对文档 Agent 模式专门调大上下文；只有把窗口撑开，模型才能跑完多步循环：

```dockerfile
FROM qwen2.5:14b-instruct-q4_K_M
PARAMETER num_ctx 32768
PARAMETER temperature 0.2
```

执行 ollama create 重新生成一个带 32K 窗口的专用配置标签。

32K 上下文绝不是免费的。Qwen2.5 14B 有四十层、GQA 八个键值头、head_dim 128。fp16 下每个 token 大概占用 160KB——三万两千多个位置就是 5.2GB 的显存开销。叠上 q4_K_M 的 8.9GB 静态权重，`nvidia-smi` 显存监控直接冲到了 14.6GB。这谁顶得住？

12GB 显存的 4070 显然装不下。Ollama 自动把一部分计算层甩给了系统内存。生成速度从正常的每秒 31 个 token 掉到了每秒 9 个 token 左右。能用，但别指望它健步如飞。把窗口锁死在 32K 之后，文档 Agent 这才开始正常吐出分析步骤。

## 2. 实测 Agent 深度编辑：Word 红线修订与 Excel 公式不是花架子

我测过的几个市面开源套壳知识库，所谓的写文档，本质上只是在聊天窗口里吐出一堆 Markdown 代码块。复制到本地 Word 里格式全乱。

SurfSense 2.3.0 让我刮目相看的正是它的实操能力。

在测试阶段，我把一份写好的服务协议上传进去。直接在 Agent 输入框下达指令：

修改第三条付款条款：将预付款比例从百分之三十下调至百分之二十，逾期违约金上调为每日千分之五，并保持其余条文引用序号自适应。

等待了大概三十秒。终端跑完了三个工具调用的往返。

系统没有直接输出一段文字，而是直接提供了一个新的文档下载链接。

用本地 LibreOffice 打开下载出来的 docx 副本，界面当场弹出了醒目的红线删除线与蓝色新增批注。预付款比例被划掉改为百分之二十。违约金修改处甚至自动带上了修订时间戳。面对这种原生的红线审阅机制，难道不比聊天窗口里贴纯文本省事得多？

更有意思的是 Excel 公式的排查测试。

我把昨天财务同事那张公式错乱的表格丢进工作台。原表在计算综合单价时漏掉了特定税率字段，导致整整一列全报 VALUE 错误。

我在 Agent 提示词里写道：

找出表格中导致数值计算错误的所有单元格，更正公式跨表引用关系，输出修复后的新表格。

模型通过内置的表格解析脚本逐行巡检。花了大概四十秒。

下载回来的 xlsx 文件里，原本报错的单元格全部被重写成了带 IFERROR 保护的动态查找公式。原表第一页那些未改动的历史账目，数值与字体样式完好无损。没有覆盖原文件。全流程在副本上施工。这种无损生成到底是怎么做到的？遇到跨表依赖时，模型会不会把单元格相对坐标算乱？我抽查了五处跨表求和，坐标全部精准咬合。

## 3. 音频转写与资源开销：低配机器的真实劝退线

2.3.0 版本新增的另一大卖点是本地音频文件转写。

支持拖入 MP3、WAV 以及 FLAC 录音。系统会调用内置的语音识别引擎生成逐字稿，并自动将其编入知识库的引用来源。

我找来一段十七分钟的技术评审录音做压测。

测试机虽然插着 RTX 4070 显卡，但 SurfSense 默认调用的转写流程主要压在 CPU 上。

十六核 CPU 占用率瞬间冲到了 88%。风扇转速直接拉满。整个十七分钟的音频，转写耗时耗了三分二十秒。

生成出来的文本质量过关：模型仅把耦合度听成了耦合渡，出现了 3 次。其余专业术语全部识别准确。但这种转写速度，真的适合日常重度会议记录吗？

我们找了一台同事平时办公用的八核轻薄本做对照。同样的十七分钟音频扔进去，轻薄本跑了整整十二分钟，键盘表面烫得没法放手，中途甚至因为内存打满差点被系统强杀进程。这难道不是在白白折磨硬件吗？

再看显存。如果你的显卡只有 6GB 或者 8GB 显存，强行跑 14B 搭配 32K 上下文，大部分模型层都会被溢出到内存里。生成速度当场暴跌至每秒 2 到 3 个 token。

光标半天蹦一个字。拿着 8GB 显存的轻薄本硬跑重度文档 Agent，能换来什么像样的体验？

要想完全留在显存里流畅运行，显存不足的设备就得退回到 7B 模型。Qwen2.5 7B 跑 32K 上下文，静态权重 4.7GB 加上 2.6GB 键值缓存，总共 7.3GB 显存。在 12GB 显卡上跑起来极为富余。

## 4. 落地部署避坑清单与真实边界

折腾完一整套离线环境，我给打算尝试的同行梳理出几条极度硬核的边界提示：

第一，别迷信开箱即用。官方文档写着填地址就行。但在原生 Linux 上跑 Docker，必须显式追加 add-host 参数。否则连容器网络都出不去。少了这个参数，前面折腾大半天不全白费了吗？

第二，硬件配置有严格门槛。显存低于 12GB 的朋友，老老实实切到 Qwen2.5 7B 模型做日常问答，别去硬扛 14B 的长上下文 Agent。

第三，Agent 输出依然需要人工最后把关。虽然它改完 Word 会给红线批注，改完 Excel 能修好公式，但商业合同的法律风险不是模型能承担的。

这东西我不推荐给所有人。

12GB 显存是入场券，再加一个愿意跟它磨一下午的耐心。两条缺一条，老老实实用商业云端接口，省下来的时间是实打实的。

最后一句多余的提醒：Agent 改完的合同，逐条用肉眼看。它不担责，你担。

你准备好亲自给文档挑刺了吗？
